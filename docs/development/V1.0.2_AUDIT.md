# V1.0.2 Repository / Reproducible Release Audit

## Purpose

V1.0.2 reduces first-publication, repository hygiene and release reproducibility risk. It intentionally does not modify FEM mathematics.

## Closed items

1. **CMake target dependency ordering**
   - `femcae_geometry` is created before `femcae_meshing` links it.
   - Clean `--target femcae_meshing` build produces both libraries.

2. **Version single-source hardening**
   - CMake project = 1.0.2.
   - Fortran version contract = 1.0.2.
   - Shared library `VERSION=${PROJECT_VERSION}`.
   - Shared library `SOVERSION=${PROJECT_VERSION_MAJOR}`.
   - Installed library is versioned as `libfemcae.so.1.0.2` on the portable validation host.

3. **Repository hygiene**
   - generated build/stage/dist paths and common compiled artifacts are rejected,
   - Apple private-key/certificate material is rejected by filename/suffix policy,
   - Git-tracked mode is used automatically when `.git` metadata is available.

4. **Deterministic source artifacts**
   - sorted archive entries,
   - fixed timestamps,
   - normalized executable/file permissions,
   - internal SHA256 manifest,
   - two independent archive runs compare byte-for-byte equal.

5. **First Git publication path**
   - source ZIP extraction,
   - hygiene check,
   - `git init -b main`,
   - initial commit,
   - `origin` setup,
   - optional GitHub CLI repository creation/push.
   - The no-push path is executed by CTest in a temporary tree.

6. **GitHub Actions hardening**
   - manual `workflow_dispatch` added to normal macOS CI,
   - concurrency cancellation for stale CI runs,
   - repository/reproducible-source gate,
   - deterministic source ZIP included in protected signed/notarized release artifacts.
