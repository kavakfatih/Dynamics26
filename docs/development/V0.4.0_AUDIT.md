## Mimari denetim

Kritik bagim yonu korunur:

```text
Assembly -> LinearSolver -> Platform backend
```

`src/assembly` icinde Accelerate header, C API veya platform kosulu bulunmaz.

Apple dokumantasyonunda default Sparse factor/solve hata handler'inin prosesi sonlandirabilecegi belirtildigi icin adapter default error policy kullanmaz; symbolic factorization `reportError` callback ile olusturulur ve hata Fortran status katmanina geri tasinir.

## Bulunan ve kapatilan hata

Debug runtime-check testinde `fem_sparsity_graph` duplicate-eleme loop'unda ilk iterasyonda onceki elemana erisilebilme riski bulundu.

Ilk kosul mantiksal `.or.` ile yazilmisti. Fortran operand evaluation icin short-circuit garantisi vermedigi icin `i == 1` dogru olsa bile diger operand `rows(i-1)` degerlendirebilirdi.

Duzeltme:

```text
if (i == 1) then
    ...
else if (current /= previous) then
    ...
end if
```

Sonuc, Debug `-fcheck=all` ile tekrar dogrulandi.

## Hata-yolu hardening

V0.4 release oncesi eklenen `unit_v040_error_paths` su davranislari kilitler:

- sparse pattern disi scatter -> `INVALID_ARGUMENT`,
- singular dense solve -> `NUMERICAL_FAILURE`,
- bilinmeyen solver backend -> `INVALID_ARGUMENT`.

## Verification sonucu

Iki adet seri TRUSS2:

```text
E = 210e9 Pa
A = 1e-4 m^2
L1 = L2 = 1 m
F = 1000 N
```

Analitik:

```text
u2 = 4.761904761904762e-5 m
u3 = 9.523809523809524e-5 m
R1x = -1000 N
```

Dense reference ve sparse CG cozumleri bu degerlerle test toleransi icinde uyumludur. Reaction equilibrium ayrica kontrol edilir.
