# FEMCAE V0.6.0 — Modal Dynamics Architecture

**Durum:** Scope complete — portable core validation tamamlandı; native macOS Accelerate/Qt/VTK CI gate açık.  
**Hedef platform:** macOS / Apple Silicon arm64  
**Çekirdek:** Modern Fortran 2018  
**GUI:** Qt 6 / C++ + optional VTK

## 1. Amaç

V0.6.0, V0.5 lineer statik yapısal çekirdeğini serbest titreşim/modal analiz yeteneği ile genişletir. Temel problem:

```text
K φ = λ M φ
ω = sqrt(λ)
f = ω / (2π)
```

Burada `K` global stiffness, `M` global mass, `φ` mode shape ve `λ = ω²` özdeğeridir.

## 2. Katman sınırları

```text
Model / Mesh / DOF / Constraints
            ↓
Element stiffness + element mass
            ↓
Ortak sparsity graph
            ↓
Global sparse K + M assembly
            ↓
ModalAnalysis
            ↓
Generalized EigenSolver facade
      ↙            ↓                ↘
Dense reference   ARPACK-NG   Accelerate/LAPACK
            ↓
λ, ω, f, M-normalized φ, residual
            ↓
C ABI modal preset
            ↓
Qt result table + VTK mode animation
```

GUI, Fortran derived type ABI'sine bağlanmaz. Mevcut mimari sözleşme korunur:

```text
Qt/C++ → stable public C ABI → Fortran engine
```

## 3. Mass matrix katmanı

`src/elements/fem_structural_mass.f90` aşağıdaki formulation'lar için mass matrix üretir:

- TRUSS2,
- 2B Euler–Bernoulli beam/frame,
- plane stress / plane strain QUAD4,
- axisymmetric QUAD4,
- HEX8.

İki baseline seçenek vardır:

- `MASS_CONSISTENT`
- `MASS_LUMPED`

Continuum lumping, consistent matrix'in row-sum dönüşümüyle yapılır. Modal analizde material density `ρ > 0` zorunludur.

## 4. Generalized eigenproblem

### 4.1 Vendor-independent reference

Dense reference backend önce:

```text
M = L Lᵀ
A = L⁻¹ K L⁻ᵀ
```

dönüşümünü yapar. Ardından symmetric Jacobi eigensolver ile:

```text
A y = λ y
φ = L⁻ᵀ y
```

çözülür.

Bu backend büyük modeller için performans hedefi değildir; doğrulama oracle'ı ve küçük problemler için deterministik baseline'dır.

### 4.2 ARPACK-NG

ARPACK-NG backend aynı generalized-to-standard dönüşümünden sonra reverse communication `dsaupd/dseupd` akışını kullanır. V0.6 baseline'ında operator dense transformed matrix matvec'tir.

**Önemli kapsam sınırı:** V0.6 ARPACK backend henüz production-scale sparse shift-invert factorization cache kullanmaz. Büyük model performans hardening'i ileriki sürümde yapılacaktır. Genel sparse `K/M` assembly buna rağmen korunur.

### 4.3 Apple Accelerate / LAPACK

macOS'ta ayrı backend generalized symmetric LAPACK `DSYGV` çağrısı ile tüm generalized eigenproblem'i çözer. Vendor API yalnız backend modülündedir; assembly ve analysis katmanına sızmaz.

Native Apple Silicon execution `.github/workflows/macos-build.yml` ile release gate'tir.

## 5. Mode normalization ve işaret sözleşmesi

Her mode için:

```text
φᵀ M φ = 1
```

mass normalization uygulanır. Eigenvector işareti fiziksel olarak tekil değildir; deterministic regression amacıyla mutlak değeri en büyük bileşen pozitif olacak şekilde işaret sabitlenir.

## 6. Modal residual

Her mode için normalize residual raporlanır:

```text
r = Kφ - λMφ
η = ||r|| / max(1, ||Kφ||)
```

Bu değer yalnız eigensolver convergence bilgisini değil, recovered generalized mode'un assembled `K/M` ile tutarlılığını da kontrol eder.

## 7. Zero / rigid-mode detection

`M` SPD olduğu sürece generalized problemdeki sıfır eigenvalue sayısı `K` nullity'sine eşittir. V0.6 modal result bu nedenle assembled active stiffness üzerinde rank/nullity estimate hesaplar ve `zero_mode_count` olarak saklar.

Bu sayı free-free continuum modellerde rigid-body modes'u, eksik constraint veya yetersiz formulation bulunan modellerde ise ek mekanizmaları da içerebilir. Bu yüzden metadata ismi fiziksel olarak daha güvenli biçimde zero-mode count olarak tutulur.

## 8. Constraint politikası

Free-vibration V0.6 baseline:

- sıfır essential constraints kabul eder,
- nonzero prescribed displacement'i reddeder,
- constraint'li DOF'ları hem `K` hem `M` active equation space'inden aynı numbering ile çıkarır.

Prestressed modal analysis V0.6 kapsamında değildir.

## 9. Beam / shell orientation hazırlığı

Element metadata'ya `orientation_frame_id` eklendi. Model wrapper, atanan local frame'in registry içinde gerçekten bulunduğunu doğrular.

Bu V0.6'da:

- beam local-axis/section orientation için altyapıdır,
- gelecekte shell director/orientation kullanımına hazırdır,
- ancak shell stiffness formulation'ının tamamlandığı anlamına gelmez.

## 10. GUI modal entegrasyonu

İlk modal GUI workflow'u arbitrary mesh editor değildir. C API'deki iki elemanlı axial modal preset'i üzerinden:

- `E`, `ρ`, `A`, `L` girdileri,
- Mode 1 / Mode 2 frekansları,
- mode seçimi,
- normalize edilmiş mode-shape animasyonu

sunulur.

Core `solve_modal_analysis()` ise preset'ten bağımsız genel model driver'ıdır.
