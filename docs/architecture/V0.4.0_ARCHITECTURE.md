# FEMCAE V0.4.0 — Sparse Assembly / Linear Solver Architecture

## 1. Amaç

V0.4.0, element-local katkilarin global equation sistemine tasinmasi ve cozulmesi icin backend-bagimsiz temel mimariyi kurar. Bu surumun ana tasarim ilkesi, FEM assembly kodunu platforma veya belirli bir sparse solver kutuphanesine baglamamaktir.

## 2. Katmanlar

```text
Mesh / Fields / DOFs / Constraints / Numbering
                    ↓
             Element DOF Map
                    ↓
             Sparsity Graph
                    ↓
              CSR Matrix
                    ↓
     Matrix / Vector Assembly + BC
                    ↓
            LinearSolver Facade
          ↙          ↓           ↘
 Dense Reference   Sparse CG   Accelerate Bridge
                                  ↓
                              C Adapter
                                  ↓
                         Apple Accelerate Sparse
```

`src/assembly` katmani `src/solver` backend ayrintilarini bilmez.

## 3. Element DOF map

`element_dof_map_t` bir element icin node-major sirada su bilgileri tasir:

- persistent `dof_ids`,
- aktif `equation_ids`,
- constrained bayragi,
- prescribed displacement degeri.

Constrained DOF icin equation ID `INVALID_ID`'dir. Bu nedenle:

```text
Physical DOF var olabilir
ama global active equation olmayabilir.
```

Bu ayrim reaction recovery ve nonzero essential boundary condition icin gereklidir.

## 4. Sparsity graph

Global graph, element equation baglantilarindan `(row_eq, col_eq)` ciftleri olusturarak kurulur.

V0.4 baseline algoritmasi:

1. her aktif equation icin structural diagonal ekler,
2. her element map'inin aktif equation ciftlerini toplar,
3. pair listesini siralar,
4. duplicate ciftleri kaldirir,
5. CSR `row_ptr/col_ind` olusturur.

Kritik nokta: global `N x N` dense adjacency matrisi kurulmaz.

Her aktif equation icin diagonal pattern'de tutulur. Baglantisiz/serbest bir DOF varsa sorun pattern kurulumunda saklanmaz; singularity solver seviyesinde gorunur.

## 5. CSR storage

`csr_matrix_t`:

```text
row_count
column_count
row_ptr(:)
col_ind(:)
values(:)
properties
```

sozlesmesini kullanir.

Index semantigi:

```text
row_ptr(1) = 1
row_ptr(n+1) = nnz + 1
col_ind     = 0-tabanli equation ID
```

`add_value` pattern disi bir entry'yi reddeder. Assembly asamasinda pattern'in sessizce degismesi yasaktir.

## 6. Matrix properties

V0.4 ile matrix metadata ilk kez solver politikasina tasinabilecek bicimde saklanir:

- general / symmetric,
- definiteness unknown / SPD expected.

V0.4 Accelerate adapter'i henuz bu metadata'ya gore Cholesky/LU secimi yapmaz; portable baseline icin general LU yolu kullanir. Gelecek backend policy bu metadata'yi kullanabilir.

## 7. Generic assembly

`assemble_matrix_by_equation` element-local matrisi equation map uzerinden global CSR values dizisine scatter eder.

Bu mekanizma semantik olarak yalniz stiffness'e bagli degildir. Ayni altyapi:

- stiffness,
- tangent,
- mass

matrisleri icin kullanilabilir.

V0.4 fiziksel mass-element formulation'i eklemez; yalniz global assembly altyapisini hazirlar.

`assemble_vector_by_equation` ayni sekilde residual/load benzeri element-local vectorleri global active equation vectorune tasir.

## 8. Essential boundary conditions

Global active system constrained DOF'lari equation listesine almaz.

Local partition:

```text
[K_aa K_ab] [u_a] = [f_a]
[K_ba K_bb] [u_b]   [f_b]
```

Prescribed `u_b` biliniyorsa aktif problem:

```text
K_aa u_a = f_a - K_ab u_b
```

olur. `assemble_stiffness_with_constraints` bu RHS terimini local matrix assembly sirasinda ekler.

Bu nedenle V0.4 sifir olmayan prescribed displacement'i destekleyen global altyapiya sahiptir.

## 9. Reaction recovery

Reaction, constrained DOF'larin equation ID'si olmadigi icin equation-vector tabanli degil persistent DOF-ID tabanlidir.

Element seviyesinde:

```text
r_e = K_e u_e - f_e
```

hesaplanir ve constrained DOF'lar uzerine accumulate edilir. Gerekirse constrained external load ayrica cikarilir.

Bu mekanizma `Node ID != DOF ID != Equation ID` sozlesmesini korur.

## 10. Solver backends

### 10.1 Dense reference

`fem_dense_reference_solver`:

- CSR -> dense conversion,
- partial pivoting Gaussian elimination,
- scale-aware singular pivot kontrolu

uygular.

Production buyuk sistem solver'i degildir. Sparse backend'leri ve verification problemlerini bagimsiz bir referansla karsilastirmak icindir.

### 10.2 Sparse CG

`fem_sparse_cg_solver`:

- CSR matvec,
- Jacobi preconditioner,
- Conjugate Gradient,
- iteration/residual statistics

sunar.

SPD sistemler icin portable sparse iterative baseline'dir.

### 10.3 Apple Accelerate Sparse direct

Platform siniri:

```text
Fortran
  ↓ ISO_C_BINDING
fem_accelerate_bridge.f90
  ↓ C ABI
fem_accelerate_adapter.c
  ↓
Accelerate/Accelerate.h
```

Non-Apple derlemede ayni C adapter sembolleri stub olarak bulunur ve backend `unavailable` raporlar. Boylece Fortran kaynak agaci platform kosuluyla parcali hale gelmez.

Apple tarafinda CSR verisi adapter icinde coordinate representation'a cevrilir, Accelerate sparse matrix olusturulur, direct factorization ve solve uygulanir.

Accelerate'in varsayilan factor/solve error handler'inin prosesi sonlandirabilen davranisi kullanilmaz. Symbolic factorization ilk kez olusturulurken `reportError` callback verilir; callback thread-local hata bayragina cevrilir ve C adapter return code uzerinden Fortran `status_t` katmanina tasinir.

V0.4 baseline direct factorization secimi `SparseFactorizationLU`'dur. Symmetric/SPD metadata ile Cholesky/LDLT policy secimi ileriki hardening maddesidir.

## 11. Minimum physical element: TRUSS2

V0.4 assembled verification'in yalniz yapay matrisle sinirli kalmamasi icin 3B iki dugumlu lineer truss local stiffness eklenmistir.

```text
K_e = (EA/L)
      [ nn^T   -nn^T
       -nn^T    nn^T ]
```

Burada `n` element unit direction vektorudur.

Bu, V0.5 genel material/section/formulation kutuphanesinin yerine gecmez; V0.4 global solver zincirinin fiziksel verification fixture'idir.

## 12. Hata politikasi

V0.4 asagidaki durumlari explicit status ile reddeder:

- graph disi equation ID,
- sparse pattern disina scatter,
- vector/matrix size mismatch,
- singular dense reference solve,
- bilinmeyen solver backend.

Release oncesi Debug runtime-check kosusunda Fortran logical `.or.` ifadesinin short-circuit garantisi olmadigi icin sparsity unique-loop'unda `i=1` iken `i-1` erisimi yapabilecek bir hata yakalanmistir. Kosul explicit `if/else if` ile duzeltilmistir. Bu olay Debug runtime checks'in release gate olarak kalmasinin gerekcesidir.

## 13. V0.5'e verilen sözleşme

V0.5 lineer structural element formulation'lari su altyapiyi hazir kabul edebilir:

- deterministic equation map,
- sparse structural pattern,
- CSR matrix storage,
- local-to-global matrix/vector scatter,
- prescribed-displacement correction,
- reaction recovery,
- dense verification solver,
- sparse iterative solver,
- macOS native direct-solver adapter siniri.

V0.5'in ana isi artik genel material/section/load modeli, gercek QUAD4/HEX8/beam stiffness formulasyonlari ve ilk Qt GUI'dir.
