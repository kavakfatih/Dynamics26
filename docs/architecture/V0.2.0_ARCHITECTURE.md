# V0.2.0 Architecture — Model / Mesh / Field / DOF / Numbering

## 1. Katman amaci

V0.2 veri modeli solver matematik katmanindan ayridir. Mesh ve DOF nesneleri stiffness matrix hesaplamaz. V0.3 element kernel bu modele baglanacak, V0.4 assembly equation map'i kullanacaktir.

```text
model_t
  |-- mesh_t
  |    |-- node_t[]
  |    `-- element_t[] -> Node IDs + Material ID + Section ID
  |-- topology_registry_t
  |-- set_registry_t
  |-- field_registry_t
  |-- dof_set_t
  |-- constraint_set_t
  |-- equation_map_t
  `-- coordinate_frame_registry_t
```

## 2. Kimlik uzaylari

Dort farkli kavram vardir:

1. **Persistent Entity ID** — Node/Element/Field vb. model kimligi.
2. **Array Position** — o anki Fortran storage konumu; implementasyon detayidir.
3. **DOF ID** — fiziksel bilinmeyenin kalici kimligi.
4. **Equation ID** — aktif lineer/nonlinear denklem sistemindeki gecici indeks.

Ornek:

```text
Node ID = 1000
nodes(1) = bu node
Ux DOF ID = 0
Ux constrained => Equation ID = INVALID_ID
Uy DOF ID = 1
Uy free        => Equation ID = 0
```

## 3. Connectivity

`element_t%node_ids(:)` yalnizca Node ID saklar. Element connectivity'yi dogrudan `nodes(i)` index'i olarak saklamak yasaktir.

V0.2, bilinen BAR2/QUAD4/HEX8 tiplerinde beklenen node sayisini ve dangling/duplicate Node ID'leri kontrol eder.

## 4. Field / DOF modeli

Bir DOF fiziksel olarak su tuple ile adreslenir:

```text
(entity_id, field_id, component)
```

DOF ID bu tuple'dan matematiksel olarak encode edilmez. Boylece field ekleme, mesh reorder ve gelecekte partitioning DOF kimlik semantigini bozmaz.

## 5. Constraints ve numbering

Essential constraint:

```text
constraint -> DOF ID -> prescribed value
```

Equation ID saklamaz. Numbering tekrar kuruldugunda constraint gecerliligini korur.

Deterministik numbering mevcut DOF storage sirasi uzerinden serbest DOF'lara `0..neq-1` verir. Bu baseline daha sonra reorder algoritmasi eklendiginde strateji arayuzune donusturulebilir.

## 6. Mixed-field hazirligi

V0.2 standard field registry:

- displacement (3),
- pressure (1),
- rotation (3).

Bu release yalnizca veri modeli ve numbering saglar. `u-p` block tangent, pressure interpolation ve inf-sup/stabilization V0.10 konusudur.

## 7. Local frames

Coordinate frame eksenleri:

- birim uzunlukta,
- birbirine dik,
- sag-el (`det > 0`)

olmak zorundadir. V0.2 frame transformation matrisi kullanarak element formulation uygulamaz; yalnizca dogru metadata ve validation saglar.

## 8. Material / section baglantisi

Element, material ve section nesnesinin kendisini sahiplenmez. Kalici `material_id` / `section_id` baglantisi tutar. Section kullanmayan elementlerde `section_id = INVALID_ID` gecerli durumdur.

Bu ayrim V0.5 ve V0.12'de material/section editorlerinin mesh storage'i yeniden tasarlamadan eklenmesini hedefler.

## 9. Complexity notu

V0.2 lookup'lari bilincli olarak lineer `O(n)` baseline'dir. API ID tabanli kuruldugu icin ileride hash map / sorted index / partition-aware lookup eklemek semantik kontrati degistirmeyecektir.
