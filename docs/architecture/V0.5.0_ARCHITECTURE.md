# FEMCAE V0.5.0 — Linear Structural FEM + First Qt GUI Architecture

## 1. Amaç

V0.5'in ana amacı V0.4 sparse global sistemini gerçek structural element/material/property katmanıyla birleştirmek ve solver çekirdeğini ilk Qt masaüstü arayüzüne bağlamaktır.

## 2. Katmanlar

```text
GUI (Qt / optional VTK)
        │
        │ stable C ABI
        ▼
API Boundary
        ▼
Analysis Driver
        ├── Model / Mesh / Fields / DOFs
        ├── Materials / Sections / Loads / Constraints
        ├── Element Formulation Dispatch
        ├── Sparse Assembly
        ├── Linear Solver Facade
        └── Result / Reaction Recovery
```

GUI'nin Fortran module ABI'sine doğrudan bağlanması yasaktır. C++ katmanı yalnız `include/femcae/femcae.h` public boundary'sini kullanır.

## 3. Formulation-topology ayrımı

Mesh topolojisi sadece düğüm bağlantısını/geometrik ailesini tanımlar. Fiziksel formulation ayrı ID'dir.

Örnek:

```text
TOPOLOGY_QUAD4
  ├── PLANE_STRESS_QUAD4
  ├── PLANE_STRAIN_QUAD4
  └── AXISYM_QUAD4
```

Analysis driver formulation registry üzerinden topology compatibility kontrolü yapar. Bu kontrol mixed u-p veya nonlinear formulation'lar eklendiğinde mevcut mesh topolojisini çoğaltmadan yeni davranış eklemeyi sağlar.

## 4. Material / section ayrımı

Lineer izotropik material:

```text
Material ID -> E, ν, density
```

Section:

```text
TRUSS -> A
PLANE -> thickness
BEAM  -> A, Iz
```

Element:

```text
Element ID
  topology_id
  formulation_id
  material_id
  section_id
```

Bu dört ID array index değildir.

## 5. Element-local DOF map

V0.5 `build_nodal_components` ile bir formulation'ın birden çok field'dan component çekmesini destekler.

2B beam örneği:

```text
node 1: UX, UY, RZ
node 2: UX, UY, RZ
```

Bu altyapı V0.6 beam/modal ve V0.10 mixed-field formulation'larında yeniden kullanılacaktır.

## 6. General LinearStaticAnalysis

Analysis driver:

```text
renumber
→ build_element_map
→ active DOF coverage validation
→ sparsity graph
→ CSR initialize
→ local stiffness dispatch
→ constrained assembly
→ nodal loads
→ linear solve
→ physical DOF reconstruction
→ reaction recovery
```

Hata politikası fail-fast + `status_t`'dir. Yanlış topology/formulation veya section kind ileride singular matrix olarak ortaya çıkmadan önce reddedilir.

## 7. Solver sınırı

V0.4 backend facade korunur:

- dense reference,
- sparse CG,
- Apple Accelerate Sparse direct.

Element ve analysis modülleri vendor solver API'si bilmez.

## 8. GUI sınırı

V0.5 GUI şu sorumlulukları taşır:

- project UI state,
- material/section/load/BC input,
- analysis action,
- result presentation,
- VTK viewport orchestration.

Engine hesabı Qt/C++ içine tekrar yazılmaz.

V0.5 public C API'ye additive `fem_demo_axial_bar()` eklenmiştir. C API major contract değişmediği için `FEM_C_API_VERSION = 1` korunur.

Generic model-handle API sonraki GUI integration adımına bırakılmıştır.

## 9. Project persistence

İlk GUI JSON dosyası `FEM_PROJECT_SCHEMA_VERSION = 1` değerini yazar ve okurken schema uyumluluğunu kontrol eder. V0.5 dosyası demo/preset kapsamındaki material, section ve load bilgilerini saklar.

Bu, V0.13 tam project serialization değildir.

## 10. VTK

VTK optional GUI dependency'dir. `QVTKOpenGLNativeWidget` üzerinden native Qt OpenGL widget içine gömülür. VTK yoksa solver ve Qt pencere katmanı çalışabilir; viewport placeholder'a düşer.

## 11. Release gate

Portable host'ta Fortran/C core testleri çalıştırılabilir. Native macOS app için ayrı gate gerekir:

- macOS arm64,
- Qt 6 build,
- VTK build,
- `.app` binary architecture check,
- install-layout check,
- core CTest matrix.

Bu gate GitHub Actions `gui-build` job'ında tanımlıdır.
