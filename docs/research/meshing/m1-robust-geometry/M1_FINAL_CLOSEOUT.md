## 4. Exact-oracle independence review

### Oracle A

`tools/meshing_oracle/exact_oracle.py` Oracle A:

- reconstructs the exact stored binary64 value through integer-ratio/Fraction arithmetic,
- uses translated determinant formulas,
- uses an exact recursive Fraction determinant for the translated insphere matrix.

### Oracle B

Oracle B:

- decodes IEEE-754 sign/exponent/fraction bits manually,
- converts all coordinates to a common exact dyadic integer scale,
- builds homogeneous orientation/lifted matrices,
- evaluates the integer determinant through a permutation expansion.

The two oracles share predicate naming, arity and sign convention, but not the coordinate reconstruction path or determinant formulation.

That is sufficient algorithmic independence for the M1 verification authority. It is not claimed to be independent organizational provenance. Hand-coded canonical signs and metamorphic identities provide an additional correlated-bug check.

## 5. Raw-bit and signed-zero review

D26PRED intentionally records binary64 bit patterns rather than decimal coordinates.

Consequences:

- no decimal parse/rounding ambiguity enters the truth corpus,
- `-0.0` can be represented and tested explicitly,
- the C++ reader reconstructs the exact bit pattern with `bit_cast`,
- predicate arithmetic treats both signed zeros as exact numerical zero,
- site identity normalizes both signed-zero encodings to canonical `+0`,
- the symbolic duplicate check uses the same zero-normalization policy.

The signed-zero policy is therefore consistent across truth fixtures, production site identity and symbolic degeneracy verification.

## 6. Duplicate canonicalization and PointId review

`canonicalizeSites()` rejects non-finite coordinates, normalizes signed zero and groups sites by a 3-component raw-bit key in an ordered map.

For identical coordinates:

- source record provenance is aggregated,
- provenance IDs are sorted,
- exactly one canonical site remains.

PointIds are assigned after deterministic key ordering, not input enumeration. Reversing input order is covered by executable tests.

The ordering is a deterministic binary64 identity ordering; it is not claimed to be a geometric Morton/Hilbert ordering. Spatial insertion ordering remains M2.

## 7. Affine dimension review

The classifier operates on canonical sites:

- no site -> Empty,
- one canonical site -> 0D,
- exact collinearity is tested through the XY/XZ/YZ orientation projections,
- a non-collinear third site establishes a plane,
- orient3d determines whether any remaining site leaves that plane.

No metric tolerance decides dimension.

A near-coplanar `2^-200` regression remains 3D, demonstrating that the decision is predicate-driven rather than epsilon-driven.

## 8. Symbolic perturbation review

The formal oracle is test-only.

It represents coordinates as exact sparse polynomials and attaches a deterministic infinitesimal hierarchy based on:

1. sorted stable PointId rank,
2. coordinate component order.

The perturbation exponent is `4^rank`. Base 4 leaves enough digit separation for the degree-2 lifted coordinates used by incircle/insphere, preventing simple exponent-sum aliasing in the supported predicate polynomial.

The sign of the lowest non-zero exponent coefficient defines the deterministic symbolic sign.

Production Delaunay tie consumption remains M2 and must be verified against this M1 oracle.

## 11. Fast-filter proof review

The implemented fast path evaluates homogeneous determinants up to lifted 5x5 insphere.

The proof document matches that implementation graph:

- 3D lift longest rounded path <= 3 operations,
- determinant permutation term <= 5 multiplications after the lift,
- worst term bound <= gamma_8,
- at most 120 signed determinant additions,
- conservative determinant path <= gamma_128,
- computed permanent relation includes gamma_8 and gamma_120 denominator corrections.

The executable coefficient is:

```text
C = 2^-43 = 1024 u
u = 2^-53
```

The derived worst coefficient is approximately `128 u`, leaving roughly an 8x coefficient margin before the additional runtime range guards.

A C++ `static_assert` protects the inequality. Overflow, suspicious underflow, non-normal nonzero intermediates or uncertified determinant magnitudes route to the exact fallback.

The fast path never returns exact Zero.

## 12. Telemetry review

Telemetry is caller-owned; there is no process-global mutable counter.

For valid calls:

```text
fastCertified + exactFallback
```

partitions successful evaluations.

Invalid inputs are counted separately:

```text
calls = fastCertified + exactFallback + invalidInput
```

`exactZero` is a subset counter inside exact fallback, not a disjoint call category.

The known Release baseline remains:

