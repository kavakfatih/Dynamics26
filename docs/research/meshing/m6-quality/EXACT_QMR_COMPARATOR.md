# M6 Research — D26QMR1 Exact Mean-Ratio Ordering Comparator

Status: RESEARCHING / numerical-contract candidate
Date: 2026-09-06

## 1. Engineering question

How can Dynamics26 compare tetrahedral mean-ratio quality:

    q_MR(A)
    vs
    q_MR(B)

with:
- deterministic results,
- no cube-root dependence,
- no pairwise quality epsilon,
- no overflow/underflow-driven sign errors,
- exact handling of binary64 inputs,
- an efficient filtered path,
- an auditable exact fallback?

The main result is:

    exact q_MR ordering
      reduces to
    exact integer-rational comparison.

No exact irrational q_MR scalar is required.

Primary references:
- M6-NUM-001 — Shewchuk adaptive exact arithmetic,
- M6-NUM-002 — Goldberg / IEEE binary floating-point properties,
- M6-NUM-003 — CGAL filtered-exact predicate architecture.

## 2. Scope boundary

This document defines a quality **ordering predicate**.

It does not:
- replace M1 Orient3D validity,
- define product quality thresholds,
- authorize M6 implementation,
- define the displayed q_MR numeric formatting,
- select a multiprecision library,
- claim exact arithmetic is needed for every metric.

The first target is only the authoritative order used by D26QV1 / D26QACC1.

## 3. Starting identity

For a positive tetrahedron:

    q_MR
      =
    12 (3V)^(2/3)/S

where:

    S
      =
    sum over the six edges of l_e^2.

Let:

    D
      =
    6V
      >
    0.

Then:

    q_MR^3
      =
    432 D^2/S^3.

Since x^3 is strictly increasing for x>0:

    q_MR(A) < q_MR(B)

iff:

    D_A^2/S_A^3
      <
    D_B^2/S_B^3.

The constant 432 cancels from every comparison.

## 4. Exact order is easier than exact value

Even if D and S are rational, the cube root used by q_MR can be irrational.

The optimizer does not need that exact real number.

It needs only:

    ComparisonResult
      in
    {Less, Equal, Greater}.

The rational invariant:

    R_MR
      =
    D^2/S^3

contains all information needed for exact q_MR order.

This is a useful numerical-design principle:

    exact decision
    does not imply
    exact construction of every reported scalar.

## 5. Binary64 as one integer lattice

For binary64:
- radix is 2,
- normal precision is 53 significant bits,
- subnormals extend the lattice down to 2^-1074.

Every finite binary64 value can therefore be represented exactly as:

    x
      =
    I_x 2^-1074

for an integer I_x.

### 5.1 Bit-level normal value

Let:
- s be the sign bit,
- E be the 11-bit raw exponent,
- f be the 52-bit fraction field.

For:

    1 <= E <= 2046

the value is normal.

Define:

    M
      =
    2^52 + f.

Then:

    x
      =
    (-1)^s
    M
    2^(E-1023-52).

Multiplying by 2^1074 gives:

    I_x
      =
    (-1)^s
    M
    2^(E-1).

No floating multiplication is required by the conceptual decoder.

### 5.2 Subnormal

For:

    E=0
    and
    f != 0,

the binary64 value is:

    x
      =
    (-1)^s
    f
    2^-1074.

Therefore:

    I_x
      =
    (-1)^s f.

### 5.3 Zero

For:

    E=0
    f=0,

canonical D26 signed-zero normalization gives:

    I_x=0.

### 5.4 Invalid non-finite patterns

For:

    E=2047,

the value is infinity or NaN.

These are rejected before meshing-quality comparison.

## 6. Integer-width bound for decoded coordinates

The largest finite normal binary64 has:

    M < 2^53
    E = 2046.

Therefore:

    |I_x|
      <
    2^53 2^2045
      =
    2^2098.

So:

    bit_length(|I_x|)
      <=
    2098.

For two finite coordinates:

    |I_x-I_y|
      <
    2^2099.

This establishes a finite worst-case exact-arithmetic width from the input format itself.

## 7. Translation removal

For tetra vertices:

    I_0,I_1,I_2,I_3

define exact relative integer vectors:

    R_1=I_1-I_0
    R_2=I_2-I_0
    R_3=I_3-I_0.

All q_MR geometry depends only on these differences.

Thus:
- large absolute model coordinates do not need to remain in later exact expressions,
- exact translation invariance is explicit,
- the reference oracle is naturally local.

## 8. Primitive integer-scale normalization

Let G be:

    gcd(
      absolute values of all non-zero scalar components
      of all tetra pairwise integer edge differences
    ).

For a non-trivial tetra:

    G > 0.

Define:

    U_i
      =
    (I_i-I_0)/G.

Then every U component is integer.

The same G is obtained if one computes the gcd from the nine non-zero-capable anchor-relative scalar
components because all pairwise differences are generated by them.

The physical relative coordinate is:

    X_i-X_0
      =
    alpha U_i

with:

    alpha
      =
    G 2^-1074.

This removes every exact common integer scale before determinant and edge-norm powers are formed.

## 9. Integer determinant and edge invariant

Define:

    d
      =
    |det(U_1,U_2,U_3)|.

Define:

    s
      =
    sum_{0<=i<j<=3}
      ||U_j-U_i||_2^2.

Both are non-negative integers.

For a valid positive non-degenerate tetra:
- d>0,
- s>0.

Because:

    D = alpha^3 d
    S = alpha^2 s,

we obtain:

    D^2/S^3
      =
    d^2/s^3.

Therefore:

    q_MR^3
      =
    432 d^2/s^3.

The binary64 lattice exponent disappears completely.

## 10. Exact comparison formula

For two already-valid positive tetrahedra A and B:

    R_A=d_A^2/s_A^3
    R_B=d_B^2/s_B^3.

Then:

    R_A > R_B

iff:

    d_A^2 s_B^3
      >
    d_B^2 s_A^3.

Define the exact integer comparison polynomial:

    C_Q(A,B)
      =
    d_A^2 s_B^3
      -
    d_B^2 s_A^3.

Then:

    sign(C_Q)
      =
    sign(q_MR(A)-q_MR(B)).

This is the D26QMR1 reference decision.

No division, square root, cube root or floating tolerance is present.

## 11. Exact equality semantics

If:

    C_Q=0,

then:

    q_MR(A)=q_MR(B)

exactly under the canonical binary64 input model.

This does not imply:
- equal coordinates,
- equal topology,
- congruent tetrahedra,
- equal other quality metrics.

It means only equal D26QMR1 mean-ratio order value.

D26QV1 handles such ties according to its quality-vector and canonical-candidate rules.

## 12. Permutation invariance

The six-edge sum s is unchanged by any vertex permutation.

A vertex permutation may change the sign of the determinant, but:

    d=|det|
    and
    d^2

are unchanged.

Therefore D26QMR1 is invariant under every permutation of the four tetra vertices.

Validity is separate:
- storage orientation must still be exact positive according to the M1/M2 contract.

## 13. Reflection and rigid-motion behavior

Translation cancels in differences.

Orthogonal rigid transforms preserve:
- edge lengths,
- |det|.

Therefore the mathematical q_MR is rigid-motion and reflection invariant.

For canonical binary64 test fixtures:
- exact integer translation can be tested directly on the lattice,
- coordinate rotations that require re-rounding create a new binary64 site set and are therefore a
  different exact input,
- exact power-of-two scale tests are preferred for bit-level reproducibility.

## 14. Exact scale behavior

For any exact common scale h applied to all relative coordinates:

    d -> h^3 d
    s -> h^2 s.

Thus:

    d^2/s^3

is unchanged.

This proves:
- physical scale invariance,
- primitive gcd normalization validity,
- independent per-tetra power-of-two scaling validity in the fast filter.

## 15. Conservative bigint width bound

After primitive normalization define:

    B
      =
    max bit length
    of any scalar pairwise edge component.

Still:

    B <= 2099.

Each scalar edge component has magnitude less than 2^B.

There are 18 squared scalar terms in s:

    s
      <
    18 2^(2B)
      <
    2^(2B+5).

The 3x3 determinant contains six triple products:

    |d|
      <
    6 2^(3B)
      <
    2^(3B+3).

Hence:

    d^2
      <
    2^(6B+6)

and:

    s^3
      <
    2^(6B+15).

A cross product obeys:

    d_A^2 s_B^3
      <
    2^(12B+21)

if the same conservative B bounds both tetrahedra.

The subtraction needs at most one additional bit:

    < 12B+22 bits.

At B=2099:

    <25210 bits.

This is roughly 3.2 KiB for one largest integer magnitude, not a total runtime-memory estimate.

## 16. Why a reference bigint oracle is attractive

The primitive-integer formulation is:
- simple,
- branch-light,
- root-free,
- platform-independent at the mathematical level,
- easy to cross-check with independent arbitrary-precision tools,
- independent of floating rounding once bits are decoded.

It is therefore a strong qualification oracle.

It may or may not be the fastest production fallback.

Backend choice remains open.

## 17. Alternative exact backend: floating expansions

Shewchuk's adaptive exact arithmetic shows that polynomial expressions over floating inputs can be
evaluated exactly with expansion arithmetic and adaptivity.

A future D26QMR1 implementation could therefore use:
- M1-compatible exact expansion primitives,
- a dedicated q_MR comparison expansion,
- or arbitrary-precision integers.

Do not select the backend before:
- reference correctness exists,
- fallback rates are measured,
- expression-size telemetry is available.

The integer-lattice oracle remains independently valuable even if production later uses expansions.

## 18. Fast filter design goal

Most mesh-quality comparisons should not require thousands of exact integer bits.

A safe architecture is:

    approximate/certified filter
      ->
    exact fallback on uncertainty.

This follows the exact-predicate architecture used successfully in robust computational geometry.

The filter must never return a guessed sign.

## 19. Independent power-of-two normalization for the filter

q_MR is scale invariant.

Therefore tetra A and tetra B may be scaled independently by exact powers of two before approximate
evaluation.

For one tetra choose k so that the largest magnitude anchor-relative coordinate component is brought
to approximately:

    [1/2,1).

Let the scaled anchor-relative components have magnitude <1.

Then any pairwise edge-coordinate difference has magnitude <2.

Consequently:

    s < 18*2^2 = 72.

Hadamard's determinant bound gives:

    |d|
      <
    (sqrt(3))^3
      =
    3 sqrt(3)
      < 5.2.

If at least one scaled relative component has magnitude >=1/2:

    s >= 1/4.

Thus the normal filtered expression can be kept far from ordinary overflow:

    1/4 <= s <72
    |d| <5.2.

Only d can become arbitrarily close to zero in a near-degenerate tetrahedron.

That is exactly where the filter should become uncertain and use exact arithmetic.

## 20. Interval filter candidate

Use outward-rounded intervals for:
- exact input doubles,
- coordinate subtraction,
- exact power-of-two rescaling,
- determinant evaluation,
- squared-edge sum.

Obtain:

    D_interval
    S_interval.

Then form an interval for:

    q3
      =
    432 D^2/S^3.

Because valid tetrahedra have S>0, a certified interval with positive S lower bound can be evaluated.

For tetra A and B:

    if upper(q3_A) < lower(q3_B)
      => A is strictly worse

    if lower(q3_A) > upper(q3_B)
      => A is strictly better

    otherwise
      => Uncertain
         -> exact fallback.

No quality epsilon appears.

## 21. Interval implementation cautions

The research contract requires containment, not a particular interval library.

Unsafe shortcuts include:
- assuming one nextafter is always enough without proof,
- ignoring subnormal underflow,
- relying on compiler FMA contraction without matching the error proof,
- changing the floating rounding mode without qualification,
- treating overlapping intervals as equality.

A filtered result is authoritative only if its enclosure proof covers the actual compiled operations.

## 22. Why overlap is not equality

Two interval estimates can overlap for many reasons:
- the true values are nearly equal,
- the intervals are conservative,
- cancellation widened an interval,
- underflow reduced filter resolution.

Therefore:

    interval overlap
      !=
    exact q_MR equality.

Overlap means only:

    filter cannot certify.

The exact stage alone can return Equal.

## 23. Static filter remains a later optimization

A Shewchuk-style static/semi-static error bound may be faster than general interval arithmetic.

But its bound must be derived specifically for:

    D_A^2 S_B^3
      -
    D_B^2 S_A^3

or an equivalent normalized score expression.

Do not reuse:
- Orient3D constants,
- InSphere constants,
- a generic machine-epsilon multiplier.

A static filter is deferred until:
- the exact oracle is executable,
- interval-filter fallback telemetry exists,
- compiler/FMA behavior is frozen for the target build.

## 24. Hardware/compiler contract

The exact integer fallback depends only on:
- the stored 64-bit coordinate patterns,
- exact integer arithmetic.

The floating filter has stronger environmental requirements.

Qualification should record:
- radix 2,
- 53-bit binary64 significand,
- expected exponent range,
- gradual-underflow behavior used by the filter,
- rounding mode,
- contraction/FMA policy,
- absence of unsafe fast-math transformations.

Debug and Release must produce identical comparison results even if filter/fallback counts differ.

## 25. Signed zero and non-finite handling

M1 canonical site identity already normalizes signed zero.

D26QMR1 follows the same input contract.

Required:
- +0 and -0 decode to the same lattice integer zero,
- NaN rejected,
- +/-infinity rejected,
- no non-finite value reaches gcd/determinant/edge arithmetic.

## 26. Degenerate and inverted tetrahedra

The quality formula alone is not a validity predicate.

Rules:

### Degenerate

    Orient3D == Zero

is rejected before quality acceptance.

### Inverted

    Orient3D == Negative

is rejected or reoriented only according to the owning topology contract before quality comparison.

### Positive

Only exact-positive candidates enter D26QMR1 acceptance ordering.

This prevents d^2 from hiding orientation sign.

## 27. Cross-check with M1

The integer determinant sign computed during the exact lattice oracle provides a useful independent
verification channel.

For every finite tetra fixture:

    sign(det_integer)
      ==
    M1 Orient3D exact sign

must hold after accounting for the same vertex ordering convention.

This does not merge M1 and M6 ownership.

It is a qualification cross-check.

## 28. Reference-oracle pseudoflow

Conceptually:

    CompareQMR(A,B):

      require finite canonical coordinates
      require A and B exact-positive

      keyA = BuildPrimitiveQmrKey(A)
      keyB = BuildPrimitiveQmrKey(B)

      left
        =
      keyA.d^2 * keyB.s^3

      right
        =
      keyB.d^2 * keyA.s^3

      return compare(left,right).

Where:

    BuildPrimitiveQmrKey(T):

      decode coordinates to binary64 lattice integers
      form exact coordinate differences
      divide common integer gcd
      compute abs integer determinant d
      compute integer edge-square sum s
      require d>0 and s>0
      return (d,s).

This is specification pseudoflow, not production code.

## 29. Candidate filtered-exact pseudoflow

Conceptually:

    CompareQMRFiltered(A,B):

      require exact-positive validity

      intervalA
        =
      CertifiedQ3Interval(A)

      intervalB
        =
      CertifiedQ3Interval(B)

      if intervalA strictly below intervalB:
          return LessFast

      if intervalA strictly above intervalB:
          return GreaterFast

      exact
        =
      CompareQMR(A,B)

      return exact with ExactFallback telemetry.

Exact equality is never returned by the interval overlap path.

## 31. Display value versus authoritative order

A floating display may show:

    q_MR(A) = 0.123456
    q_MR(B) = 0.123456

after rounding to user-visible precision while D26QMR1 still proves one is better.

Therefore:
- displayed q_MR is a diagnostic approximation,
- D26QMR1 comparison is authoritative for topology acceptance,
- audit logs should be able to record exact comparison result/path when a near-tie matters.

Do not force the display formatter to become an exact algebra system.

## 32. Determinism contract

For the same:
- canonical binary64 coordinates,
- vertex sets,
- D26QMR1 version,

the exact comparator result must be identical across:
- repeated runs,
- Debug/Release,
- allocation order,
- operation enumeration order,
- macOS arm64 supported machines.

The filter may take a different path only if the final exact comparison result is unchanged.

Reference qualification should also require deterministic filter telemetry for the frozen compiler
contract if telemetry itself becomes a replay artifact.

## 36. Current conclusion

D26QMR1 can be significantly stronger than a floating quality metric comparison.

For canonical binary64 input:

    mean-ratio ordering
      ->
    integer lattice
      ->
    primitive scale removal
      ->
    integer determinant / squared-edge invariant
      ->
    exact cross multiplication.

This gives:
- no root,
- no division,
- no quality epsilon,
- exact ties,
- finite worst-case arithmetic width,
- direct compatibility with D26QV1 sorting,
- a safe filtered-exact acceleration path.

The next step is verification-design refinement and, only when implementation is authorized, an
exact-only reference comparator before any optimized filter.

This document does not authorize production M6 code.
