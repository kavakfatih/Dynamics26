# Dynamics26 V1.1.0 — GUI / UI / UX Araştırma ve Uygulama Planı

**Durum:** Onaylı çalışma planı  
**Öncelik:** Aktif sonraki sürüm  
**Amaç:** Mevcut engineering/debug GUI'yi profesyonel macOS-first CAE kullanıcı deneyimine dönüştürmek.  

## 1. Ana hedef

V1.1.0'da yeni solver fiziği geliştirmek ana hedef değildir. Mevcut CAD, meshing, material, load/BC, nonlinear, mixed `u-p`, contact ve results altyapısı, gerçek bir mühendisin terminal/debug preset kullanmadan yönetebileceği ortak CAE workflow'a bağlanacaktır.

Başarı kriteri yalnız daha modern görünen bir arayüz değildir. Asıl hedef:

```text
New Project
   ↓
Geometry
   ↓
Materials / Sections
   ↓
Connections
   ↓
Mesh
   ↓
Analysis
   ↓
Loads / Boundary Conditions
   ↓
Preflight
   ↓
Solve
   ↓
Results
```

zincirinin tutarlı, öğrenilebilir ve hata önleyici bir kullanıcı deneyimiyle yürütülmesidir.

## 2. Araştırma kapsamı

Her Dynamics26 modülü tek bir rakip uygulamadan kopyalanmayacaktır. Aşağıdaki sistemler, kendi güçlü oldukları çalışma alanları için araştırılacaktır:

| Dynamics26 alanı | Araştırma referansları | Ana araştırma sorusu |
|---|---|---|
| Application shell | ANSYS Mechanical, COMSOL, Apple HIG | Navigator, toolbar, inspector ve viewport dengesi nasıl kuruluyor? |
| Model / project tree | ANSYS Outline, COMSOL Model Builder, Simufact process tree | Model nesneleri nasıl hiyerarşik ve anlaşılır sunuluyor? |
| Geometry | ANSYS/Discovery, HyperMesh, Simcenter, Abaqus/CAE | Body/face/edge selection, CAD repair ve geometry operation akışı nasıl? |
| Materials | ANSYS Engineering Data, Abaqus Property, COMSOL | Malzeme oluşturma, model seçme, veri doğrulama ve assignment nasıl? |
| Sections | Abaqus, ANSYS | Beam/shell section definition ve orientation nasıl yönetiliyor? |
| Connections / Contact | ANSYS, Abaqus, Marc/Mentat, Simufact | Contact pair, automatic detection ve interaction property UX nasıl? |
| Meshing | ANSYS Meshing, HyperMesh, Simcenter | Global/local controls, method choice ve quality feedback nasıl? |
| Analysis / Steps | Abaqus Step, ANSYS Analysis, Marc/Mentat, Simufact | Analiz türleri, step/increment ayarları ve advanced settings nasıl ayrılıyor? |
| Loads / BC | ANSYS, Abaqus, COMSOL | Geometry scoping, coordinate system, magnitude ve glyph feedback nasıl? |
| Solve monitor | Marc/Mentat, Abaqus, ANSYS | Job status, Newton iteration, warning ve convergence nasıl gösteriliyor? |
| Results | HyperView, Abaqus Visualization, ANSYS Solution | Contour, probe, path, section, history ve compare workflow nasıl? |
| macOS interaction | Apple Human Interface Guidelines | Sidebar, inspector, toolbar, sheet, menu ve keyboard davranışı nasıl native tutulur? |

## 3. Araştırma yöntemi

Her gözlem aşağıdaki karar şablonundan geçer:

```text
Observed Pattern
      ↓
Kullanıcı problemi nedir?
      ↓
Neden işe yarıyor / neden işlemiyor?
      ↓
CAE mühendislik riskine etkisi nedir?
      ↓
Dynamics26 için karar:
ADOPT / ADAPT / REJECT
```

Araştırma çıktılarında ekran veya ikon kopyalama hedeflenmez. Proprietary görseller, metinler, kaynak kod veya implementation alınmaz. Yalnız genel UX deseni, bilgi mimarisi ve mühendislik workflow'u incelenir.

Ana ilkeler:

- 3D viewport ekranın birincil çalışma alanıdır.
- Sol panel komut listesi değil, **project object hierarchy** olur.
- Sağ Inspector yalnız seçilen nesnenin özelliklerini gösterir.
- Alt panel kalıcı büyük log alanı değil, gerektiğinde açılan drawer olur.
- Context toolbar seçilen workspace/nesneye göre değişir.
- Basic ve Advanced seçenekler ayrılır.
- Solver-internal terminoloji kullanıcıya zorunlu olarak gösterilmez.

## 6. Selection architecture

Selection sistemi GUI'nin temel servislerinden biri olarak tasarlanmalıdır.

CAD seçim seviyeleri:

- Body
- Face
- Edge
- Vertex

FEM seçim seviyeleri:

- Node
- Element
- Facet / Element Face

Planlanan interaction özellikleri:

- selection filters,
- single/multi selection,
- box selection,
- add/remove/toggle,
- hide/show/isolate,
- fit selection,
- selection history,
- named selections,
- persistent geometry scoping,
- hover/preselection highlight,
- clear visual distinction between CAD and FEM entity selection.

## 7. Inspector architecture

Her nesnenin property editor'ı ortak bir yapı kullanmalıdır:

```text
Inspector
├── Definition
├── Scope
├── Coordinate System
├── Parameters
├── Display
└── Advanced
```

Kurallar:

- Birimler property editor tarafından açıkça gösterilir.
- Invalid değer sessizce kabul edilmez.
- Required alanlar ve default değerler ayrılır.
- Advanced solver parametreleri ilk ekranda kullanıcıyı boğmaz.
- Property değişiklikleri undo/redo command model üzerinden yürütülür.

## 8. Geometry workspace

Araştırma başlıkları:

- import/open behavior,
- assembly/body tree,
- topology selection,
- transparent/isolate modes,
- repair/heal feedback,
- CAD operation history için uygun soyutlama,
- geometry validity diagnostics,
- named selections,
- CAD-to-mesh provenance görünürlüğü.

V1.1, V1.2 General CAD'in tüm feature'larını uygulamak zorunda değildir; fakat GUI mimarisi V1.2 özellikleri eklendiğinde yeniden yazılmamalıdır.

## 9. Material workspace

Hedef akış:

```text
Create Material
   ↓
Select Material Family
   ↓
Select Constitutive Model
   ↓
Enter / Import Test Data or Parameters
   ↓
Validate Units / Stability
   ↓
Preview
   ↓
Assign to Bodies
```

Özellikle hyperelastic materials için model, volumetric behavior, parameters ve validation durumu açıkça ayrılmalıdır. Advanced formulation seçimi normal material definition ekranından ayrılabilir.

## 10. Connections / Contact workspace

Planlanan UX:

```text
Create Connection
   ↓
Select Type
   ↓
Scope Side A / Side B
   ↓
Interaction Property
   ↓
Detection / Orientation Check
   ↓
Visual Preview
   ↓
Validation
```

Contact normal, master/slave veya symmetric behavior gibi kavramların kullanıcıya hangi seviyede gösterileceği research ile belirlenecektir.

## 11. Mesh workspace

Ana UI alanları:

- global mesh control,
- local mesh controls,
- mesh method,
- element order,
- sizing,
- quality criteria,
- generate/update,
- mesh statistics,
- quality visualization.

V1.3 General FEM Meshing henüz gelmeden önce GUI, structured HEX8 baseline'ı destekler; ancak object model ileride TRIA/QUAD/TET/HEX ve local controls eklenmesini taşımalıdır.

## 13. Preflight / validation sistemi

`Solve` öncesi model kontrolü V1.1'in temel kullanılabilirlik özelliklerinden biri olacaktır.

Örnek:

```text
MODEL CHECK

✓ Geometry valid
✓ Materials assigned
✓ Mesh generated
✓ Analysis configured

⚠ Body 4 has no material
✕ Fixed support has empty scope
✕ Contact pair Side B is empty
```

Amaç kullanıcının solver başladıktan sonra anlaşılması zor bir hata almasını azaltmaktır.

Preflight kontrolleri UI katmanında uydurulmaz; mümkün olduğunca application/core model validity API'lerinden gelir.

## 14. Solve Monitor

Normal solve ekranı yalnız console log olmayacaktır.

Planlanan bilgiler:

- analysis state,
- current step/increment,
- nonlinear iteration,
- residual norm,
- displacement correction norm,
- energy criterion varsa,
- line-search/cutback events,
- warning/error summary,
- elapsed time,
- stop/cancel control.

Raw developer log ayrı bir diagnostics görünümünde tutulabilir.

## 15. Results workspace

V1.1 mevcut result baseline'ı için kullanılabilir ortak UX kurar; V1.12 Advanced Postprocessing bu mimariyi genişletir.

Navigator örneği:

```text
Results
├── Total Deformation
├── Stress
├── Strain
├── Contact
├── Probe
└── Charts
```

Result inspector en az şunları gösterecek şekilde tasarlanmalıdır:

- field,
- component/invariant,
- location (`Integration Point`, `Nodal`, vb.),
- averaging,
- deformation scale,
- min/max,
- active load step / mode / time.

## 16. macOS-first UX ilkeleri

- Native menu bar kullanımı.
- Standard keyboard shortcuts.
- Sidebar / inspector davranışının macOS beklentileriyle uyumlu olması.
- Gereksiz ribbon karmaşıklığından kaçınma.
- Toolbar context-aware ve öz olmalı.
- Light/dark appearance testleri.
- Standard open/save/sheet/dialog davranışı.
- Retina/HiDPI viewport ve ikon kalitesi.
- Accessibility ve keyboard navigation en azından mimari olarak göz önüne alınmalı.

## 17. Dynamics26 visual design ilkeleri

- Modern-minimal, engineering-first.
- Küçük ve tutarlı corner radius.
- İnce ayırıcılar.
- Gereksiz shadow kullanılmaması.
- Renk yalnız anlam taşımak için kullanılmalı: selection, warning, error, result scale vb.
- Ana 3D viewport görsel olarak baskın kalmalı.
- Bilgi yoğunluğu azaltılırken mühendislik verisi saklanmamalı; hierarchy ve disclosure ile yönetilmeli.

Güncellenecekler:

- About,

- documentation başlıkları,

Ayrı audit gerektirenler:

- `FEMCAE_*` CMake cache/options,

## 22. V1.1 release acceptance

V1.1.0 kapanmadan önce en az şu senaryo GUI üzerinden tamamlanabilmelidir:

```text
Launch Dynamics26
→ New/Open Project
→ Import/choose geometry
→ Assign material
→ Create/generate supported mesh
→ Create supported analysis
→ Apply supported BC/load
→ Preflight
→ Solve
→ Inspect supported result
→ Save project
→ Reopen project
```

Bu acceptance yalnız desteklenen mevcut solver baseline'ı için geçerlidir; V1.2+ özellikleri tamamlanmış gibi gösterilmez.
