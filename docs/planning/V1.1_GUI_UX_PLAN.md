# Dynamics26 V1.1.0 — Nonlinear Analysis Workflow Acceleration Plan

**Durum:** Aktif çalışma planı  
**Engineering core:** `V1.0.2`  
**Current GUI milestone:** `V1.1.0-beta.2`  
**Next milestone:** `V1.1.0-beta.3 — Minimum Usable Nonlinear Analysis Workflow`

V1.1'in kalan amacı artık yalnız UI polish veya ayrı bir Results workspace değildir. Amaç kullanıcının minimum ama gerçek nonlinear static structural modeli hazırlayıp çalıştırabildiği ve sonuçlarını inceleyebildiği bir CAE workflow'unu tamamlamaktır.

# 1. Beta.3 exit workflow

Beta.3 ancak aşağıdaki gerçek product workflow tamamlanırsa kapanır:

```text
1. New Project
2. Import STEP
3. Select body
4. Create / assign material
5. Generate mesh
6. Insert Static Structural analysis
7. Enable Nonlinear / Large Deformation
8. Select face(s) → Fixed Support
9. Select face(s) → Force or Pressure
10. Preflight
11. Solve
12. Watch convergence
13. Insert Total Deformation / Equivalent Stress / Reaction result
14. Probe / min-max / step selection
15. Save / reopen project
```

Bu listedeki bir adım yalnız verification helper ile çalışıyorsa product workflow tamamlanmış sayılmaz.

```text
      Uy = 0
      Uz = 0
```

Minimum viewport feedback:

- scoped faces selected/highlighted when object active,
- support glyphs readable but not excessive,
- glyphs disappear/suppress consistently,
- stale scope appears as warning, not silent reassignment.

# 6. Force / Pressure UX

Inspector baseline:

```text
Force 1

Scope
  Method: Geometry Selection | Named Selection
  Geometry: 3 Faces

Definition
  Type: Total Force | Force per Area | Pressure
  Define By: Vector | Components
  Coordinate System: Global
  X / Y / Z or Magnitude + Direction
```

Initial implementation may expose only validated modes; unavailable modes disabled with explanation.

## 6.1 Total Force

A total resultant must not be interpreted as “force value per selected face”. Dynamics26 baseline:

```text
F_total = one resultant for entire selected scope
A_ref   = sum of selected reference areas
t_ref   = F_total / A_ref
```

Then element-face load contribution is integrated consistently.

## 6.2 Pressure

Pressure direction follows surface normal. Large-deformation follower pressure is a separate capability and must be explicitly supported before enabled.

## 6.3 Viewport arrows

Load glyph design:

- sample points distributed over selected faces,
- density based on visible area/viewport scale,
- common vector direction for total/global force,
- local normal direction for pressure,
- arrow length normalized for readability,
- one legend/magnitude annotation,
- arrows never define actual nodal load values.

Curved surface pressure may need per-glyph local normal.

# 9. Analysis Settings

Basic:

```text
Analysis Type: Static Structural
Behavior: Linear | Nonlinear
Large Deformation: On/Off
Load Factor End: 1.0
Stepping: Automatic
```

Advanced nonlinear controls use existing persistent `NonlinearSolverControls` fields:

- Full / Modified Newton,
- maximum iterations,
- adaptive stepping,
- initial/min/max load increment,
- line search,
- residual relative tolerance,
- displacement relative tolerance.

A control cannot be editable as an active setting if current solver consumer does not read it.

# 10. Preflight

Minimum blocking diagnostics:

- no geometry,
- no material assignment,
- unsupported material model,
- no mesh,
- invalid/inverted mesh,
- empty/stale support scope,
- empty/stale load scope,
- unconstrained rigid-body model warning/error,
- nonlinear consumer unavailable,
- unsupported element/formulation,
- invalid solver controls.

Warnings and errors are distinct.

# 11. General nonlinear product consumer

The main Beta.3 engineering task is connecting a supported real model subset to the existing nonlinear solver core.

```text
Document
→ SolverInputBuilder
→ Validated Analysis Snapshot
→ C ABI
→ Fortran nonlinear solver
→ SolverSessionTelemetry
→ ResultSet
```

Product subset must be explicitly documented, for example supported element/material/load combinations. No silent widening of capability.

Required behavior:

- DirectLinear only for linear analysis,
- nonlinear analysis uses nonlinear consumer,
- solver failure does not corrupt document,
- Cancel state is safe,
- telemetry updates UtilityWorkspace,
- final converged result produces result dataset,
- failed step keeps diagnostics but no fake completed result.

# 12. Convergence workspace

Beta.2 foundation is retained.

User summary:

```text
Running | Load 0.55 | Increment 0.05 | Iteration 4
Residual: decreasing
```

Advanced table:

- step/attempt,
- iteration,
- load factor,
- Δλ,
- residual norm,
- relative residual,
- displacement increment,
- relative displacement,
- line-search alpha,
- converged,
- available mixed/contact metrics.

Unsupported columns show `Unavailable`, not zero.

# 14. Beta.3 acceptance model

At least one deterministic benchmark project must exercise the full UI chain.

Recommended first model:

- simple 3D HEX8-compatible block/cantilever,
- linear elastic material first,
- geometric nonlinearity enabled,
- fixed face,
- distributed face force,
- multiple increments,
- displacement/stress/reaction result.

Then add hyperelastic single-block benchmark only when product material consumer is connected.
