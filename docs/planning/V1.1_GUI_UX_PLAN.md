# Dynamics26 V1.1.0 — Supported Nonlinear Workflow Acceleration Plan

**Durum:** Aktif Beta.3 çalışma planı  
**Engineering core:** `V1.0.2`  
**Current GUI milestone:** `V1.1.0-beta.2`  
**Next:** `V1.1.0-beta.3 — Supported Nonlinear Workflow Vertical Slice`

V1.1'in amacı artık “nonlinear ile ilgili ekranlar var” demek değildir. Amaç kullanıcının **desteklenen capability envelope içinde** gerçek model state'i üzerinden setup → solve → convergence → results akışını tamamlamasıdır.

# 1. Beta.3 exit workflow

Beta.3 release modeli:

```text
1. New Project
2. Create parametric box veya import box-compatible STEP
3. Select body
4. Create / assign Linear Elastic material
5. Generate structured HEX8 mesh
6. Insert Nonlinear Static analysis
7. Enable Large Deformation
8. Select face(s) → Fixed Support
9. Select face(s) → Total Force
10. Preflight / Capability Check
11. Solve with general nonlinear product consumer
12. Watch Newton convergence
13. Inspect Total/Directional Deformation, Stress, Reactions
14. Probe / min-max
15. Save / reopen setup
16. Undo/Redo persistent setup changes
```

Keyfi STEP volume solve Beta.3 exit criterion değildir; mevcut mesher bunu desteklememektedir.

# 2. UX design rule — capability-aware, not optimistic

Her object Inspector mümkünse üç katman gösterir:

```text
Scope
Definition
Advanced
```

Her aktif setting backend capability ile eşleşir.

Status semantics:

- **Ready** — current workflow consumer supports it.
- **Setup only** — engineering definition kaydedilebilir fakat current solver consumer desteklemiyor.
- **Unavailable** — bu analysis/formulation için anlamlı değil.
- **Stale** — source geometry/mesh revision değişmiş.
- **Invalid** — eksik veya fiziksel/numerical olarak geçersiz.

Disabled control tooltip yalnız “unsupported” demez; gerekli capability'yi söyler.

# 7. Force UX + real load physics

```text
Force 1

Scope
  Geometry     3 Faces

Definition
  Load Type    Total Force
  Define By    Components / Vector
  Coord System Global
  Fx/Fy/Fz     ... N
  Configuration Reference
```

Future load types may be shown only with explicit capability status:

- Force per Area,
- Pressure,
- follower/current-area load.

## Total Force semantics

```text
A_ref = sum(reference areas)
t_ref = F_total / A_ref
f_e   = ∫Γe Nᵀ t_ref dΓ
```

### Required load acceptance

1. Single QUAD4 facet constant traction.
2. Multiple equal facets.
3. Multiple unequal facets.
4. Shared nodes.
5. Different mesh densities.
6. Multi-face selected scope.
7. Non-axis-aligned planar face when supported.

Assertions:

```text
sum(nodal equivalent force) ≈ requested resultant
sum(moment of nodal force) ≈ analytical surface-load moment
result independent of viewport arrow count
```

## Glyph rendering

- common direction for global Total Force,
- local normal for Pressure,
- sample density based on visible/physical area,
- capped count,
- stable scale after zoom,
- magnitude displayed once or by legend,
- arrows do not map one-to-one to FEM nodes.

# 8. Pressure UX

Pressure is not a Force alias.

```text
traction = -p n
```

Inspector should expose a `Configuration` concept before follower pressure is enabled:

- Reference — verified first if implemented,
- Current/Deformed — disabled until geometric nonlinear follower-load tangent is verified.

Curved surface pressure arrows use local normals.

# 12. Preflight as a user workflow, not just validator

Preflight rows should navigate to the failing object.

Blocking categories:

### Geometry/Mesh
- unsupported geometry by current mesher,
- no mesh,
- stale mesh,
- invalid/inverted element,
- unsupported topology/formulation.

### Materials
- no assignment,
- invalid parameters,
- unsupported constitutive model,
- incompressibility/formulation mismatch.

### BC/Loads
- empty scope,
- stale scope,
- no constraints,
- no load,
- load mode unsupported,
- unresolved boundary facets.

### Solver
- nonlinear consumer unavailable,
- invalid controls,
- incompatible matrix/backend,
- estimated model exceeds dense-reference guard.

Warnings:

- low mesh quality,
- aggressive initial increment,
- potentially singular setup heuristic,
- result definition unavailable.

# 13. SolverInputBuilder

GUI service should not call a demo C function by constructing special geometry assumptions.

```text
AnalysisService
→ preflight
→ SolverInputBuilder
→ AnalysisSnapshot
→ C ABI adapter
```

Builder responsibilities:

- resolve Geometry scopes to current mesh facets/nodes,
- assemble surface-load equivalent forces,
- map ObjectIds to solver IDs without using UI indices,
- convert mm/MPa etc. to SI,
- map material/formulation IDs,
- validate C ABI ranges/capacities,
- freeze source signatures.

# 14. Nonlinear product C ABI

Recommended API style: versioned structs/descriptors instead of continuing demo-specific argument expansion.

Conceptual:

```text
fem_nonlinear_model_input_v1
fem_nonlinear_options_v1
fem_nonlinear_history_entry_v1
fem_nonlinear_result_v1

fem_solve_nonlinear_model_v1(input, options, output)
```

Requirements:

- `bind(C)` compatible fields only,
- explicit `api_version` / `struct_size`,
- pointer + count pairs,
- caller/solver ownership documented,
- no hidden allocation ownership ambiguity,
- status/error codes,
- no direct Fortran type exposure.

# 15. Newton workflow UX

ANSYS reference shows Full/Modified choices and line search/automatic stepping as distinct numerical tools. Dynamics26 UI keeps normal user controls minimal.

During solve:

```text
Load 0.55 / 1.00
Increment 0.05
Iteration 4 / 25
Residual 2.4e-5 ↓
Line Search α 0.72
```

Advanced table:

- attempt,
- accepted step before/after,
- iteration,
- λ,
- Δλ,
- abs/relative residual,
- displacement increment,
- relative displacement,
- α,
- converged,
- cutback,
- min J if available.

No metric unavailable in solver history is displayed as zero.

# 16. Solve state and cancellation

```text
Idle
→ Preflight
→ Ready
→ Solving
→ Completed | Failed | Cancelled
```

- Solve uses frozen snapshot.
- UI remains responsive if async execution is introduced.
- Cancel requests safe solver boundary; no partial document mutation.
- Failure keeps telemetry/messages.
- Only converged accepted state creates valid ResultSet.

# 18. Beta.3 automated acceptance matrix

## A. Scope authoring

- real CAD Face selection,
- Fixed Support from Selection,
- Force from Selection,
- one Undo reverses one logical authoring transaction,
- Redo restores IDs/references correctly,
- save/reopen persistent scope.

## B. Surface load physics

- resultant conservation,
- moment conservation,
- unequal facet area weighting,
- mesh-density independence of resultant,
- glyph-count independence.

## C. Solver bridge

- input snapshot deterministic,
- product geometry arrays used,
- no demo geometry,
- nonlinear controls consumed,
- no DirectLinear fallback,
- failure status typed.

## D. Newton

- multi-increment convergence,
- at least one cutback case,
- line-search telemetry case,
- Full vs Modified method identity,
- invalid option rejection.

## E. Results

- displacement field size matches mesh,
- reaction equilibrium,
- stress field defined at declared location,
- probe/min-max finite,
- stale result when source input changes.

# 19. Beta.3 reference benchmark

First benchmark deliberately simple:

- rectangular solid,
- structured HEX8,
- fixed face,
- opposite-face Total Force,
- geometric nonlinearity,
- finite-strain product element path,
- multiple increments.

This model tests workflow architecture without conflating arbitrary meshing, contact and hyperelasticity.

Second benchmark after first is green:

- nonuniform face mesh / unequal facet distribution to verify load mapping.

Hyperelastic benchmark belongs to product material consumer milestone, not Beta.3 by implication.
