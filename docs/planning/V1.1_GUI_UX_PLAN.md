# Dynamics26 V1.1.0 — GUI / UI / UX Araştırma ve Uygulama Planı

**Durum:** Onaylı çalışma planı  
**Güncel temiz GUI baseline:** V1.1.0-alpha.3.1.1  
**Aktif sonraki milestone:** V1.1.0-alpha.3.2 — Selection & Scoping Foundation  
**Amaç:** Mevcut engineering/debug GUI'yi profesyonel macOS-first CAE kullanıcı deneyimine dönüştürmek.  

## 1. Ana hedef

V1.1.0'da yeni solver fiziği geliştirmek ana hedef değildir. Mevcut CAD, meshing, material, load/BC, nonlinear, mixed `u-p`, contact ve results altyapısı, gerçek bir mühendisin terminal/debug preset kullanmadan yönetebileceği ortak CAE workflow'a bağlanacaktır.

Başarı kriteri yalnız daha modern görünen bir arayüz değildir. Asıl hedef:

```text
New Project
   ↓
Geometry
   ↓
Materials / Sections
   ↓
Connections
   ↓
Mesh
   ↓
Analysis
   ↓
Loads / Boundary Conditions
   ↓
Preflight
   ↓
Solve
   ↓
Results
```

zincirinin tutarlı, öğrenilebilir ve hata önleyici bir kullanıcı deneyimiyle yürütülmesidir.

## 2. Araştırma kapsamı

Her Dynamics26 modülü tek bir rakip uygulamadan kopyalanmayacaktır. Genel interaction pattern'leri araştırılır; proprietary görünüm, metin, ikon veya kaynak kod kopyalanmaz.

| Dynamics26 alanı | Araştırma referansları | Ana araştırma sorusu |
|---|---|---|

| Model / project tree | ANSYS Outline, COMSOL Model Builder, Simufact | Model nesneleri nasıl hiyerarşik ve anlaşılır sunuluyor? |

## 3. Araştırma yöntemi

Her gözlem aşağıdaki karar şablonundan geçer:

```text
Observed Pattern
      ↓
Kullanıcı problemi nedir?
      ↓
Neden işe yarıyor / neden işlemiyor?
      ↓
CAE mühendislik riskine etkisi nedir?
      ↓
Dynamics26 için karar:
ADOPT / ADAPT / REJECT / DEFER
```

Araştırma sonucu selection konusunda çıkan ana kararlar:

- ANSYS: transient selection ile Named Selection / engineering scope ayrımı **ADOPT**.
- COMSOL: active feature'ın kabul ettiği entity level'a göre context-aware selection **ADAPT**.
- Abaqus/CAE: procedure-aware filter ve explicit multi-selection semantics **ADAPT**.
- HyperMesh: connected/similar/advanced selection araçları **DEFER**.
- NX/Simcenter: Selection Intent benzeri ilişkili seçim mantığı **DEFER**.
- Apple HIG: focus, hover ve selection'ın aynı state olmaması **ADOPT**.
- Qt/macOS: fiziksel Command modifier semantiğinin doğru Qt mapping ile ele alınması **ADOPT**.
- VTK: click/hover için CellPicker, ileri area selection için hardware selector yaklaşımı **ADAPT**.

## 6. Selection & Scoping Architecture — Alpha.3.2

Selection sistemi GUI'nin temel servislerinden biridir ve Alpha.3.2'nin ana geliştirme konusudur.

### 6.1 Temel mimari ayrım

```text
Selection Filter / Policy
        ↓
Picking / Preselection
        ↓
Transient Current Selection
        ↓ Apply / Assign
Persistent Engineering Scope
```

Dört katman aynı veri olarak ele alınmayacaktır.

- Filter/Policy hangi entity tiplerinin seçilebileceğini belirler.
- Preselection hover sonucu geçici adaydır.
- Current Selection viewport/UI state'tir.
- Persistent Scope document/model state'tir.

### 6.2 Domain ve kind modeli

```text
SelectionDomain
- ProjectObject
- Geometry
- Mesh

SelectionKind
- Object
- Body
- Face
- Edge
- Vertex

- Element
- Facet
```

Alpha.3.2 kullanıcı-visible kapsamı:

Edge/Vertex/Node/Element/Facet sonraki milestone'larda açılır.

### 6.3 CAD topology provenance P0

Mevcut mimari kural değişmez:

> CAD Geometry != Display Tessellation != FEM Mesh

Gerçek Face selection için hedef zincir:

```text
CAD Body
  ↓
CAD Face
  ↓
Display Tessellation
  ↓
Triangle
  ↓
GeometryEntityId(Face)
```

Display triangle yalnız provenance taşır. Triangle index hiçbir zaman CAD Face kimliği olarak kullanılmaz.

Gerekli veri kontratı en az şunları desteklemelidir:

- Body ID,
- Face ID,
- parent Body ID,
- triangle → source Face mapping,
- geometry source revision,
- stale mapping tespiti.

### 6.4 Selection Core servisleri

Önerilen yerleşim:

```text
gui/core/
  SelectionTypes.h
  SelectionManager.h
  SelectionManager.cpp
  SelectionPolicy.h
```

`SelectionItem` gelecekte tekrar tasarım gerektirmeden en az şunları taşıyabilmelidir:

```text
SelectionItem
- domain
- kind
- projectObjectId
- geometryEntityId
- parentGeometryId
- meshEntityId
- sourceRevision
```

### 6.5 State ayrımı

Aşağıdaki kavramlar açıkça farklıdır:

- **Preselection** — hover candidate.
- **Current Selection** — seçilmiş entity collection.
- **Primary Selection** — current selection içindeki current/anchor entity.
- **Project Current Object** — Navigator/Inspector aktif nesnesi.
- **Persistent Scope** — BC/load/contact/material/mesh feature tarafından saklanan scope.

Selection state `DocumentCommandManager` / document undo stack'ine girmez. Model özelliğini değiştiren persistent scope assignment ise undoable command olabilir.

### 6.6 Selection Policy

Context-aware policy, aktif komutun kabul ettiği selection türünü bildirir.

| Context | İzin verilen entity |
|---|---|
| Neutral Geometry | Body / Face |
| Material Assignment | Body |
| Fixed Support | Face |
| Surface Force / Pressure | Face |
| Contact Side A / B | Face |
| Body Mesh Control | Body |
| Face Mesh Control | Face |

Alpha.3.2'de bütün bu workflows migrate edilmese de API bu ihtiyaçları taşıyabilmelidir.

### 6.7 Body / Face filter UI

Geometry context'te ilk visible selection filter:

```text
Selection  [ Body | Face ]
```

`Auto` ilk sürüme alınmaz. Automatic ambiguity handling ve candidate cycling ileri selection milestone'una bırakılır.

### 6.8 macOS pointer / keyboard contract

İlk interaction kontratı:

| Interaction | Sonuç |
|---|---|
| Click | Replace |
| Shift + Click | Add |
| Command + Click | Toggle |
| Empty-area click | Clear |
| Esc | Clear |
| Secondary click selected entity | Selection korunur, context menu açılır |
| Secondary click unselected entity | Entity primary/current olur, context menu açılır |

Qt/macOS uygulamasında fiziksel Command tuşu Qt modifier semantiğinde `Qt::ControlModifier` üzerinden değerlendirilir. `Qt::META` eklenmez.

Option/Alt selection modifier olarak kullanılmaz; Orbit/Pan navigation davranışıyla çakışmaz.

### 6.9 Preselection / selection rendering

Hover ve committed selection ayrı semantic render role kullanır.

```text
Hover      → Preselection
Click      → Selection
```

Kurallar:

- preselection persistent değildir,
- multi-selection bütün seçili geometry entity'lerini render eder,
- highlight CAD entity seviyesinde yapılır; display triangle kullanıcıya selection identity olarak gösterilmez,
- Light/Dark mode'da iki state açık biçimde ayırt edilir.

Status feedback örneği:

```text
Body 1 › Face 12
```

### 6.10 Navigator ↔ Viewport ↔ Inspector

- Navigator Body seçimi viewport'ta ilgili Body selection'ını oluşturabilir.
- Viewport Body selection ilgili Navigator Body'yi current object yapar.
- Viewport Face selection parent Body'yi Navigator current object olarak tutabilir.
- Face'ler project tree'ye binlerce child node olarak eklenmez.
- Inspector project object özellikleri ile current geometry selection summary'sini ayırır.

Örnek summary:

```text
SELECTION
Type      Face
Selected  3
Body      Body 1
Primary   Face 27
```
