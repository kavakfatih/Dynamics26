## Surface-force presentation correction

The previous actor-wide rotation transformed absolute glyph seed positions around the world
origin. Vector direction could look correct while the arrow grid moved away from its face.
The corrected VTK pipeline orients each glyph at its own real boundary-facet center.

`BoundaryGlyphLayout.h` selects at most five load seeds, spread deterministically over the
scope. One main arrow and smaller representative arrows use the same normalized engineering
force vector. Multi-face scope stays one Total Force. Zero/nonfinite force and effectively
suppressed loads create no arrows. No normal-vector fallback is used.

CAD identity, FEM facet provenance and display glyph positions remain separate.
Glyph count/density does not enter surface integration or the solver snapshot.
Force Details describes uniform reference traction and consistent FE surface integration;
Components/Global remains the supported authoring mode.

## Research decisions

- [Qt QSplitter](https://doc.qt.io/qt-6/qsplitter.html): child-index collapse settings require inserted children; zero-size collapse and splitter movement are synchronized with the existing panel visibility state.
- [VTK vtkGlyph3D](https://vtk.org/doc/nightly/html/classvtkGlyph3D.html): per-point vectors orient glyphs locally. A global actor rotation must not rotate world-space seed locations.

Independent geometric verification checks transformed rendered arrow vertices, not only
the intended direction metadata. No vendor code or solver algorithm was copied.
