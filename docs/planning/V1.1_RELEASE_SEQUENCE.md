## V1.1.0-alpha.1 — macOS Application Shell

Amaç, mevcut çalışan Qt/VTK/OCCT/C API/Fortran yollarını yeniden yazmadan sonraki bütün V1.1 çalışmalarını taşıyacak macOS-first pencere iskeletini oluşturmaktır.

### Kapsam

- kullanıcıya görünen uygulama kimliği `Dynamics26`,
- native `QMainWindow` / macOS window frame ve native traffic lights korunması,
- VTK/QOpenGLWidget ile güvenli native-window davranışı,
- document-title alanı (`Untitled.d26` başlangıç placeholder'ı),
- modern ve kompakt macOS toolbar/navigation katmanı,
- 3D viewport'u birincil çalışma alanı yapan üçlü ana split: Navigator | VTK Viewport | Inspector,
- side panel show/hide altyapısı,
- bottom utility area iskeleti: Solver | Convergence | Graph | Table | Messages | Log,
- bottom utility alanının başlangıçta collapsed/hidden olması,
- native macOS Menu Bar,
- hard-coded light-only styling yerine system appearance,
- Light/Dark Mode'un Qt/macOS sistem palette'i üzerinden doğal çalışması,
- mevcut solver, VTK, geometry, mesh ve project migration yollarının korunması,
- ana shell üzerinde kullanıcıya gösterilen komutların gerçek bir işleve bağlı olması; yalnız gelecek sürüm placeholder'ı olan ölü kontrollerin ana UI'da gösterilmemesi.

### Bilinçli olarak kapsam dışı

- tam Navigator project object modelinin yeniden yazılması — alpha.2,
- tam command bus / undo-redo mimarisi — alpha.3,
- uçtan uca preflight/model validation — alpha.4,

### Acceptance criteria

1. Qt GUI kaynakları macOS/arm64 GUI job'unda derlenir.
2. Mevcut VTK viewport yolu kaybolmaz.
3. Mevcut geometry/mesh/material/analysis yolları compile-time olarak korunur.
4. Native bundle smoke ve strict Mach-O audit full clean gate içinde gevşetilmez.
5. Uygulama kullanıcıya `Dynamics26` adıyla görünür; solver/internal compatibility isimlerinin kalması açıkça belgelenir.
6. Main window üçlü split ve bottom utility mimarisini taşır.
7. Hard-coded yalnız-light-mode global style kaldırılır; system appearance kullanılır.
8. CI sonucu çalıştırılmadan teknik PASS ilan edilmez.
9. Gerçek macOS ekranında üst bölüm çok katmanlı eski tip gri Qt toolbar/ribbon görünümü oluşturmamalıdır; toolbar/navigation katmanı kompakt ve içerik-öncelikli olmalıdır.
10. Navigator ve Inspector başlangıçta boş/legacy/debug yüzey olarak görünmemeli; en azından anlamlı empty state veya gerçek bağlı içerik göstermelidir.
11. Ana shell üzerinde görünen birincil buton/komutlar çalışır olmalıdır. Gelecek milestone placeholder'ları ana komut yüzeyinde tıklanabilir sahte özellik olarak sunulmaz.

### 2026-08-29 gerçek macOS UX incelemesi — FAIL kaydı

Kullanıcının gerçek uygulamadan paylaştığı ekran görüntüsü ve interaction geri bildirimi Alpha.1'in görsel/işlevsel kabul kriterlerini karşılamadığını göstermiştir.

Tespitler:

- üç yatay katman (`QToolBar` + metin workspace satırı + metin command-hint satırı) gereksiz dikey alan kullanıyor ve eski Qt/macOS görünümü veriyor,
- `Navigator` metin düğmesi, küçük text-only workspace düğmeleri ve Search/Solve/About yerleşimi hedeflenen modern macOS 26/27 tasarım diliyle uyuşmuyor,
- sol Navigator pratikte boş bir yüzey gibi görünüyor,
- sağ Inspector legacy paneli/siyah arka planı ve eski tablo yapısını görünür biçimde taşıyor,
- shell içindeki bazı komutlar yalnız placeholder/hint veya disabled action; kullanıcı bunları gerçek özellik olarak kullanamıyor,
- mevcut `Dynamics26Shell` yaklaşımı legacy `MainWindow` widget/action'larını görünür metinlerinden arayıp yeniden etiketlediği için gerçek application-shell ownership oluşturmuyor,
- bu nedenle yalnız kozmetik QSS düzeltmesi yeterli değildir.

Corrective karar:

1. Alpha.2'ye geçmeden önce Alpha.1 application shell yeniden ele alınacaktır.
2. Legacy `MainWindow` görünümünü sarmalayıp yeniden etiketlemek yerine yeni shell'in layout/toolbar/sidebar/inspector ownership'i birinci sınıf olacaktır; çalışan VTK/OCCT/C API/Fortran servis yolları korunacaktır.
3. Ana shell'deki sahte/placeholder komut yüzeyleri kaldırılacak; yalnız çalışan komutlar görünür olacaktır.
4. Apple HIG'in güncel macOS toolbar/sidebar/material ilkeleri ve Qt'nin güncel macOS platform davranışı doğrultusunda native/system-semantic görünüm hedeflenecektir.
5. Görsel kabul için en az Light Mode, Dark Mode ve 14-inch MacBook Pro boyutunda gerçek screenshot review zorunludur.

## CI yaklaşımı

CI iki farklı amacı aynı pahalı GUI job'unda birleştirmeyecektir.

### Fast engineering GUI gate — normal push / pull request

GitHub-hosted Apple Silicon üzerinde:

```text
Checkout
→ GUI dependencies
→ configure
→ femcae_gui target build
→ GUI migration test build
→ migration gate
→ arm64 GUI architecture gate
```

Bu hızlı kapıda her push için standalone deployment, full dependency fixup, ad-hoc codesign, strict bundle audit ve yaklaşık 150 MB app artifact upload tekrarlanmaz. Bunlar kaynak kodunun derlenebilirliğini doğrulamak için gerekli değildir.

### Clean standalone bundle/release gate — workflow_dispatch / milestone

GitHub-hosted Apple Silicon temiz runner korunur:

```text
Clean configure
→ full GUI/core build
→ full tests
→ install/deploy
→ bundle fixup
→ strict Mach-O audit
→ codesign
→ bundle smoke
→ artifact
```

Full clean gate CI'yı hızlandırmak amacıyla gevşetilmez; yalnız günlük source-iteration kapısından ayrılır.

### Self-hosted runner

Trusted MacBook runner gerektiğinde hızlı native iteration için kullanılabilir. Release/reproducibility kanıtı yine clean GitHub-hosted gate ile alınır. Self-hosted kullanımında güvenlik nedeniyle yalnız trusted `main`/manuel akışlar tercih edilir.
