## V1.1.0-beta.3 — Minimum Usable Nonlinear Analysis Workflow

### Main objective

```text
Geometry
→ Material
→ Mesh
→ Analysis
→ Fixed Support / Force / Pressure
→ Preflight
→ Nonlinear Solve
→ Convergence
→ Results
```

### Required work packages

1. Selection/scoping productivity completion.
2. Fixed Support face workflow.
3. Force/Pressure face workflow.
4. Correct load/support viewport glyphs.
5. Material assignment minimum.
6. Mesh generate/quality minimum.
7. Nonlinear Analysis Settings.
8. General nonlinear product solver consumer.
9. Convergence integration.
10. Results MVP.
11. Save/reopen and failure recovery.
12. Native macOS acceptance.

### Capability rule

Beta.3 is not complete if nonlinear solve still exists only in verification helpers.

A nonlinear analysis:

- must not silently execute `DirectLinear`,
- must be blocked if its current element/material/load combination is unsupported,
- must expose actual solver telemetry,
- must create result data only from a real converged product solve.

## V1.1.0-rc.1 — Workflow Hardening

RC scope:

- real-device keyboard/mouse/trackpad acceptance,
- Light/Dark polish,
- large viewport model interaction regression,
- project persistence/reopen,
- Cancel/failure recovery,
- stale state behavior,
- diagnostics wording,
- native bundle/release audit,
- no unsupported capability leakage.

New solver mathematics is not the main RC objective.

## V1.1.0 stable exit

Stable V1.1 requires at least one documented nonlinear static structural workflow that a user can reproduce from geometry import through result inspection.

Minimum classification:

```text
Core workflow        FEATURE WORKS ✅
Automated regression TEST PASSED ✅
Native macOS audit   TEST PASSED ✅
USER VALIDATED       requires physical user acceptance
```
