# Dynamics26 V1.1 — GUI / UI / UX Release Sequence

**Durum:** Onaylı ve aktif plan  
**Ana dal:** `main`  
**Engineering core tabanı:** V1.0.2  
**Hedef final sürüm:** V1.1.0  
**Güncel temiz GUI baseline:** V1.1.0-alpha.3.1.1  
**Sıradaki planlanan çalışma:** V1.1.0-alpha.3.2 — Selection & Scoping Foundation  

Bu belge V1.1 GUI dönüşümünü doğrulanabilir ön sürümlere böler. Ayrı feature/fix branch açılmaz; çalışma `main` üzerinde ilerler. Bir kilometre taşı yalnız kodun bulunmasıyla değil, ilgili testlerin çalışması, CI kanıtı ve gerekiyorsa gerçek macOS kullanıcı doğrulamasıyla kapanır.

## 1. Güncel baseline

V1.1.0-alpha.3.1.1 temiz entegrasyon baseline'ı aşağıdaki mimariyi taşır:

- native macOS-first `QMainWindow` application shell,
- gerçek Project Navigator / ProjectModel / ProjectTreeModel,
- contextual Details/Inspector host,
- unified CommandRegistry ve document command/undo-redo altyapısı,
- DependencyEngine ile engineering status invalidation,
- Geometry / Mesh / Material / Analysis servis ayrımı,
- application-owned viewport input router + camera controller,
- VTK viewport, OCCT geometry, C++ meshing ve Fortran solver yollarının korunması,
- proje migration ve GUI navigation testleri,
- trusted Apple Silicon self-hosted doğrulama ve hosted core Debug/Release doğrulaması.

Alpha.3.1.1 sürümünün amacı yeni özellik eklemek değil, Alpha.3.x geliştirmesinin üzerine kurulacağı temiz kaynak/CI baseline'ını sağlamaktır.

## 3. Tarihsel Alpha.1 corrective kaydı

2026-08-29 gerçek macOS ekran incelemesinde ilk Alpha.1 implementation'ı teknik olarak derlenmesine rağmen görsel/interaction kabulünü karşılamadı. Tespit edilen ana problemler; legacy Qt toolbar katmanları, boş/legacy Navigator-Inspector yüzeyleri, placeholder komutlar ve legacy MainWindow ownership'inin yeni shell tarafından gerçek anlamda devralınmamış olmasıydı.

Corrective çalışma ile application shell, Navigator, Inspector, command architecture ve viewport ownership yeniden ele alındı. Bu kayıt tarihsel kök neden olarak korunur; **aktif geliştirme aşaması artık Alpha.1 değildir.**

## 4. V1.1.0-alpha.3.2 — Selection & Scoping Foundation

### 4.1 Amaç

Dynamics26'nin gelecekteki Geometry, Material, Mesh, BC, Load, Contact ve Results workflow'larının kullanacağı tek, merkezi, topology-aware seçim altyapısını kurmak.

Bu sürümde yeni solver fiziği, yeni constitutive model, yeni nonlinear/contact formulation veya genel-purpose meshing algoritması eklenmez.

Temel ayrım:

```text
Selection Filter / Policy
        ↓
Picking + Preselection
        ↓
Transient Current Selection
        ↓ Apply / Assign
Persistent Engineering Scope
```

`Current Selection` kullanıcı arayüzünün geçici durumudur. `ScopeReference` ise document/model state'tir. Bu iki kavram aynı veri veya aynı undo davranışı olarak ele alınmayacaktır.

### 4.2 P0 — CAD topology provenance

Gerçek Face selection için display triangle ile CAD topology arasındaki provenance açık olmalıdır.

Hedef zincir:

```text
CAD Body
  ↓
CAD Face
  ↓
Display Tessellation
  ↓
Triangle
  ↓
GeometryEntityId(Face)
```

Kural:

> CAD Geometry != Display Tessellation != FEM Mesh

Display triangle yalnız CAD Face kimliğinin provenance bilgisini taşır; CAD Face'e dönüşmez ve FEM facet olarak yorumlanmaz.

Alpha.3.2 kapanmadan önce Body ve Face kimlikleri, parent ilişkisi ve source revision doğrulanmalıdır.

### 4.3 Selection Core

Planlanan temel tipler:

```text
SelectionDomain
- ProjectObject
- Geometry
- Mesh

SelectionKind
- Object
- Body
- Face
- Edge
- Vertex
- Node
- Element
- Facet
```

Alpha.3.2'de aktif feature kapsamı:

- Project Object,
- CAD Body,
- CAD Face.

Edge/Vertex/Node/Element/Facet tipleri gelecekteki API stabilitesi için veri modelinde tanımlanabilir; ancak bu sürümde kullanıcıya tamamlanmış feature olarak sunulmaz.

Önerilen servisler:

```text
gui/core/
  SelectionTypes.h
  SelectionManager.h/.cpp
  SelectionPolicy.h
```

`SelectionItem` en az domain, kind, project object kimliği, geometry entity kimliği, parent geometry kimliği ve source revision bilgisini taşıyabilecek şekilde tasarlanır.

### 4.4 Selection state modeli

Aşağıdaki durumlar birbirinden ayrılır:

- **Preselection:** hover sonucu aday entity; persistent değildir.
- **Current Selection:** seçilmiş entity kümesi.
- **Primary Selection:** multi-selection içindeki current/anchor entity.
- **Project Current Object:** Navigator/Inspector'ın aktif document object'i.
- **Persistent Scope:** BC/load/contact/material/mesh feature tarafından saklanan engineering scope.

Selection değişiklikleri document `QUndoStack`'ine girmez. Persistent scope veya model property değişikliği ise document command modeli üzerinden undoable olabilir.

### 4.5 Selection Policy

Selection sistemi context-aware olmalıdır. Her aktif işlem hangi domain/kind kombinasyonlarını kabul ettiğini açıkça bildirir.

Örnek intent/policy'ler:

| Context | İzin verilen entity |
|---|---|
| Neutral Geometry | Body / Face |
| Material Assignment | Body |
| Fixed Support | Face |
| Surface Force / Pressure | Face |
| Contact Side A / B | Face |
| Body Mesh Control | Body |
| Face Mesh Control | Face |

Alpha.3.2'de bütün workflow'lar yeniden yazılmayacaktır; fakat `SelectionPolicy` ve future `ScopeReference` kontratı bu bağlamları taşıyabilecek şekilde kurulacaktır.

### 4.6 Viewport interaction

İlk macOS interaction kontratı:

| Interaction | Sonuç |
|---|---|
| Click | Replace selection |
| Shift + Click | Add |
| Command + Click | Toggle |
| Empty-area click | Clear |
| Esc | Clear |
| Secondary click on selected entity | Selection korunur, context menu açılır |
| Secondary click on unselected entity | Entity primary/current olur, context menu açılır |

Qt/macOS notu: fiziksel Command tuşu Qt modifier semantiğinde `Qt::ControlModifier` üzerinden ele alınır; `Qt::META` kullanımı eklenmez.

Option/Alt selection modifier olarak kullanılmaz; mevcut navigation/orbit davranışıyla çakışmasına izin verilmez.

### 4.7 Body / Face filter

Geometry context için ilk kullanıcı-visible filter:

```text
Selection  [ Body | Face ]
```

`Auto` Alpha.3.2 kapsamına alınmaz. Ambiguous automatic selection ve candidate cycling daha ileri selection sürümlerine bırakılır.

### 4.8 Preselection ve highlight

Hover ile committed selection birbirinden görsel ve state olarak ayrılır:

- `RenderRole::Preselection` benzeri ayrı semantic role,
- `RenderRole::Selection` committed selection için,
- multi-selection bütün seçilmiş CAD entity'leri aynı selection set üzerinden render eder,
- preselection hiçbir zaman document state veya persistent scope oluşturmaz.

Viewport status feedback örneği:

```text
Body 1 › Face 12
```

### 4.9 Navigator ↔ Viewport ↔ Inspector

- Navigator'da Body seçimi viewport'ta ilgili CAD Body selection'ını oluşturabilir.
- Viewport'ta Body seçimi Navigator current object'ini ilgili Body'ye getirir.
- Viewport'ta Face seçimi Navigator ağacına her Face'i node olarak eklemez; parent Body current object olarak korunur.
- Inspector project object ile geometry selection bilgisini aynı şey gibi göstermemelidir.
- Selection summary; type, count, primary entity ve gerektiğinde scope listesi gösterebilir.

### 4.10 Navigation collision guard

Selection ile camera navigation açık bir interaction state modeliyle ayrılır. Orbit/Pan/Zoom gesture başladıysa click-pick callback'inin yanlışlıkla selection üretmesine izin verilmez.

En az şu davranışlar test edilir:

- orbit entity seçmez,
- pan entity seçmez,
- zoom entity seçmez,
- orientation cube click'i body/face pick'e düşmez,
- secondary click yanlışlıkla navigation başlatmaz.

### 4.11 ScopeReference kontratı

Alpha.3.2'de bütün BC/material/contact workflow'ları migrate edilmese de transient selection'ın document state'e güvenli şekilde çevrilebileceği bir scope kontratı tanımlanır.

Scope en az şunları koruyabilmelidir:

- entity domain/kind,
- stable/persistent geometry identity,
- geometry source revision veya stale-detection bilgisi,
- multi-entity collection,
- validation status.

Geometri replace/edit sonrası stale scope sessizce geçerli kabul edilmez.

```text

```

### Trusted self-hosted Mac

```text
Clean configure
→ full GUI/core build
→ full tests
→ install/deploy
→ bundle fixup
→ strict Mach-O audit
→ codesign

→ artifact
```

Self-hosted başarı release/reproducibility kanıtı yerine geçmez; milestone kapanışlarında gerektiğinde clean hosted bundle gate çalıştırılır.
