# Dynamics26 V1.1.0-beta.1 — Engineering Inspectors Plan

## Amaç

Beta.1'in amacı mevcut engineering domain service'lerini kopyalamadan, kullanıcıya gerçek CAE object'leri üzerinde profesyonel ve tutarlı Inspector authoring deneyimi sağlamaktır.

Bu milestone yeni bir solver fiziği veya ikinci bir validation/state sistemi kurmaz. Inspector katmanı authoritative model state'in görünür ve düzenlenebilir kullanıcı yüzüdür.

## Source baseline

- Engineering core: `V1.0.2`
- GUI baseline: `V1.1.0-alpha.4`
- Alpha.4 automated closeout baseline: `b4c2f78e9345a0c50534248a2868afd0306a8040`
- Product target: macOS / Apple Silicon arm64
- UI: Qt 6
- Viewport: VTK
- CAD topology: OCCT
- Build/test: CMake + Ninja + CTest + GitHub Actions

## Mimari kurallar

### 1. Inspector state sahibi değildir

Inspector:

- domain service state'ini okur,
- kullanıcı edit'ini canonical command/service yoluna gönderir,
- aynı engineering state'in ikinci kopyasını tutmaz,
- domain validation kurallarını yeniden yazmaz.

### 2. Identity ayrımı korunur

```text
ObjectId
GeometryEntityId
MeshEntityId
```

aynı kimlik uzayı değildir.

Ayrıca:

```text
CAD Geometry != Display Tessellation != FEM Mesh
```

kuralı tüm Inspector ve scoping davranışlarında korunur.

### 3. Mutation + Undo

Persistent engineering model'i değiştiren kullanıcı işlemleri:

```text
UI edit
→ canonical command / authoritative service
→ model mutation
→ dependency invalidation
→ document Undo transaction
→ Inspector refresh
```

yolunu izlemelidir.

Transient selection, navigation, hover ve preselection document Undo history'sine girmez.

### 4. Validation

- Preflight için tek source of truth: `AnalysisService::preflight()`.
- Inspector local form-validation yalnız veri girişinin sentaktik/geçici UI uygunluğu için kullanılabilir.
- Engineering validity için ikinci bağımsız validator kurulmaz.

## Beta.1 çalışma paketleri

## B1.1 — Material Inspector

### Hedef

Material project object'i seçildiğinde gerçek material state'ini profesyonel Inspector formunda göstermek ve düzenlemek.

### Minimum kapsam

- Material adı / identity bilgisi,
- material type / supported model bilgisi,
- mevcut linear-static material property'leri,
- unit-aware numeric editing,
- assignment bilgisi / kullanılan body veya object bağlamı,
- invalid veya eksik property için açık diagnostic presentation,
- edit sonrası dependency invalidation,
- Undo / Redo ile tam state recovery.

### Acceptance

- Inspector açılması mutation üretmez.
- Bir material property edit'i tam bir document Undo transaction üretir.
- Undo exact önceki değeri geri getirir.
- Assigned analysis varsa gerekli solution state `Out of Date` olur.
- Preflight sonucu aynı authoritative service üzerinden güncellenir.

## B1.2 — Contact Inspector + Contact Definition Contract

### Hedef

Alpha.4'te placeholder seviyesinde kalan ContactRegion'ı gerçek engineering consumer'a dönüştürmek.

### Tasarım prensibi

Sahte contact validator oluşturulmaz. Önce gerçek contact-definition domain contract tanımlanır; sonra Inspector bunun UI yüzü olur.

### Minimum domain contract

- persistent Contact object / `ObjectId`,
- contact pair veya equivalent source/target scope,
- scope'ların gerçek persistent engineering identity taşıması,
- contact formulation/type alanı için genişlemeye açık enum/contract,
- enabled/suppressed state,
- dependency + stale scope davranışı,
- Preflight entegrasyonu.

### İlk UI kapsamı

- Contact adı,
- source / target scope,
- active/suppressed durumu,
- scope navigation,
- stale/dangling scope presentation,
- desteklenen ilk formulation seçimi,
- canonical mutation + Undo.

### Acceptance

- Contact object model graph'ta gerçek object'tir.
- Source/target scope display primitive index tutmaz.
- CAD/FEM scope kimlikleri domain-correct persistent reference üzerinden saklanır.
- invalid contact definition authoritative Preflight'e blocking issue olarak girebilir.
- Undo/Redo contact definition'ı exact restore eder.

## B1.3 — Mesh Inspector

### Hedef

Mesh project object'i için generated mesh state'i, source revision/generation bilgisi ve kullanıcı-authorable mesh controls'ü tek Inspector yüzünde toplamak.

### Minimum kapsam

- generated / not generated state,
- mesh generation counter/revision,
- node / element / facet count,
- source geometry revision,
- desteklenen global mesh controls,
- generate / clear navigation/action surface,
- stale FEM scope bilgisi,
- current mesh validity summary.

### Acceptance

- Inspector display state'i `MeshService` ile tutarlıdır.
- `mesh.generate` ve `mesh.clearGenerated` canonical command/service yolları korunur.
- regenerate sonrası eski FEM scope silent rebind edilmez.
- node/element/facet identity display index'ten türetilmez.

## B1.4 — Analysis Inspector

### Hedef

Analysis object'i için procedure, solve readiness, load/BC özeti, solution lifecycle ve result state'ini tek contextual Inspector yüzünde sunmak.

### Minimum kapsam

- analysis adı / procedure,
- active support count,
- active load count,
- mesh/material readiness,
- Preflight summary,
- solver state,
- solved / out-of-date / unsolved state,
- result availability,
- canonical Preflight / Solve actions.

### Acceptance

- Analysis Inspector ikinci preflight state tutmaz.
- `Run Preflight` ve `Solve` mevcut command registry yolu üzerinden çalışır.
- solved model input mutation sonrası `Solution Out of Date` görünür.
- Undo exact previous valid signature/state'i restore ederse out-of-date temizlenir.

## B1.5 — Inspector UX consistency

Tüm Engineering Inspector'larda ortak görünüm kuralları:

- macOS-first native Qt appearance,
- Light / Dark system palette,
- global hand-written QSS yok,
- gereksiz gradient yok,
- ince separator,
- kompakt ama okunabilir spacing,
- section header hiyerarşisi tutarlı,
- label/value alignment tutarlı,
- clipping/overlap olmamalı,
- keyboard focus görünür ve erişilebilir olmalı.

## Test stratejisi

Her çalışma paketi için mümkün olduğunca aşağıdaki katmanlar kullanılacaktır:

1. domain/service unit or contract test,
2. Inspector binding acceptance,
3. Undo/Redo regression,
4. dependency / stale-state regression,
5. application-level composition acceptance,
6. macOS arm64 build,
7. trusted self-hosted native validation,
8. Light / Dark visual audit.

## Uygulama sırası

Önerilen sıra:

```text
B1.1 Material Inspector
→ B1.2 Contact Definition + Contact Inspector
→ B1.3 Mesh Inspector
→ B1.4 Analysis Inspector
→ B1.5 UX consistency + full regression
```
