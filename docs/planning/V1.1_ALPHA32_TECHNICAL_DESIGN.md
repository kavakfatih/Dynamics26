# Dynamics26 V1.1.0-alpha.3.2 — Technical Design

**Milestone:** V1.1.0-alpha.3.2 — Selection & Scoping Foundation  
**Baseline:** V1.1.0-alpha.3.1.1 clean integration baseline  
**Branch policy:** `main` only  
**Scope:** architecture + implementation contract for CAD Body/Face selection, selection state, scoping foundation and macOS interaction  
**Non-goal:** new solver physics, new constitutive model, new contact formulation, general-purpose meshing or BC/load schema migration

---

## 1. Source-of-truth findings

Alpha.3.2 is not starting from zero. The current source already contains several required foundations:

- `GeometryDocument` owns stable hashed `GeometryEntityId` values and supports `Assembly`, `Body`, `Face`, `Edge`, `Vertex`, `Surface`, `Curve` entities.
- `OcctStepImporter` already creates Face entities for each imported Body, stores the OCCT shapes, stores Face→Body parent relationships and records a runtime CAD revision.
- `MeshFacet::sourceGeometryId` already carries CAD provenance; the structured HEX8 bridge therefore already knows the six CAD face IDs for the supported axis-aligned STEP-box path.
- `GraphicsWorkspace` already exposes Body/Face filter actions, but Face availability is incorrectly coupled to `mesh_->hasMesh()` and `selectionFilterChanged` is not yet wired into a central selection policy.
- `ViewportWidget` already uses `vtkCellPicker`, but geometry display currently assigns every display triangle the Body ID. Real CAD Face provenance is lost during tessellation.
- `ViewportWidget` currently has only one `highlighted` geometry ID and the highlight rebuild path depends on `cachedMesh`; imported CAD geometry therefore has no independent topology-aware highlight pipeline.
- `Dynamics26MainWindow::handleGeometryPick()` directly interprets a picked geometry ID as one of six `BoxFace` values. This is a temporary application-shell bridge, not a scalable selection architecture.
- `ProjectNavigator` is correctly based on `QTreeView + ProjectTreeModel` and is intentionally single-selection at project-object level. Geometry Face entities should not be exploded into thousands of Navigator nodes.
- `EngineeringStatusBar` already has an explicit selection field and can remain the lightweight hover/selection feedback surface.
- `SupportDefinition` and `LoadDefinition` currently use `BoxFace`. Alpha.3.2 must not migrate these working analysis definitions yet.

Two current-source mismatches must be treated as Alpha.3.2 P0 issues:

1. `Dynamics26MainWindow::syncViewport()` displays only `geometry_->bodies().first()` in normal geometry view, while the Navigator can contain multiple imported Bodies.
2. Geometry highlight is mesh-cache driven; selection rendering must be split from FEM-mesh highlighting so CAD selection works before mesh generation.

## 2. Architectural invariants

The following rules are mandatory:

### 2.1 Geometry / display / mesh separation

```text
CAD Geometry != Display Tessellation != FEM Mesh
```

A display triangle may carry provenance to a CAD Face, but the triangle is never treated as the CAD Face itself and is never a solver element.

### 2.2 Project object selection != geometry selection

```text
Project Current Object  !=  Geometry Current Selection
```

Examples:

- Navigator current object: `Body 1`
- Geometry current selection: `Face 12, Face 18`
- Inspector object: `Fixed Support 1`
- Persistent engineering scope: `Face 12, Face 18`

These four states may coexist and must not be collapsed into one ID.

### 2.3 Transient selection != persistent scope

```text
Filter / Policy
    ↓
Picking / Preselection
    ↓
Transient Selection
    ↓ Apply / Assign
Persistent ScopeReference
```

Transient selection is UI/view state and does not enter the document undo stack. Scope assignment is model state and may be undoable.

### 2.4 Selection is not document undo

The following must not create `QUndoStack` entries:

- hover/preselection,
- click selection,
- multi-selection changes,
- changing Body/Face filter,
- clearing selection,
- primary-selection changes.

Persistent scope assignment in later milestones may use `DocumentCommandManager`.

## 3. Geometry provenance design

### 3.1 Preserve the existing public `GeometryTessellation` contract

`GeometryTessellation` is already part of the C++ geometry API. To minimize unnecessary ABI/layout risk, Alpha.3.2 should prefer an additive companion type instead of changing the existing struct layout.

Recommended additive type:

```cpp
struct TopologyTessellation {
    GeometryTessellation display;
    std::vector<GeometryEntityId> triangleFaceIds;
};
```

Contract:

```text
triangleFaceIds.size() == display.triangles.size()
```

Each `triangleFaceIds[i]` is the CAD `Face` entity that produced `display.triangles[i]`.

The body remains available as `display.sourceGeometryId`.

### 3.2 OCCT importer cache

Current importer already stores each Face shape and its parent Body. Alpha.3.2 should make the Body→ordered Face record explicit so tessellation never has to guess topology identity after the fact.

Recommended internal cache:

```text
bodyId
  └── [ FaceRecord ]
          ├── faceId
          └── TopoDS_Face
```

The tessellator should iterate these cached Face records after `BRepMesh_IncrementalMesh` rather than re-exploring the Body without identity.

This gives the exact pipeline:

```text
Body ID
  ↓
FaceRecord(faceId, TopoDS_Face)
  ↓
Poly_Triangulation
  ↓
Display triangle
  ↓
triangleFaceIds[i] = faceId
```

No geometric matching, bounding-box inference or triangle-index-as-face-ID shortcut is allowed.

### 3.3 Runtime revision semantics

`GeometryDocument::revision()` is a runtime mutation token. It increments on clear/add/mutable entity operations.

Therefore:

- use `sourceRevision` to invalidate transient selection/preselection when the active CAD document changes;
- do not treat the raw revision integer as a cross-session persistent topology identity;
- persistent scope rebind must ultimately use stable geometry identity such as `persistentKey` plus validation, not revision equality alone.

Alpha.3.2 only establishes this contract. Advanced stale/rebind behavior belongs to Alpha.3.4.

### 3.4 GeometryService additions

Recommended additive API:

```cpp
std::optional<TopologyTessellation>
displayTopologyTessellation(GeometryEntityId bodyId,
                            double linearDeflection = 0.15) const;

QVector<GeometryEntityId> faces(GeometryEntityId bodyId) const;
const GeometryEntity *entity(GeometryEntityId id) const noexcept;
GeometryEntityId parentBody(GeometryEntityId id) const noexcept;
```

Existing `displayTessellation()` remains available for compatibility.

For multi-body display, add either:

```cpp
QVector<TopologyTessellation> displayTopologyScene(...) const;
```

or build that vector in the shell by calling `displayTopologyTessellation()` for all Bodies.

The service remains the CAD owner; it does not own UI selection state.

## 4. Selection core

Add:

```text
gui/core/SelectionTypes.h
gui/core/SelectionManager.h
gui/core/SelectionManager.cpp
gui/core/SelectionPolicy.h
```

### 4.1 SelectionDomain

```cpp
enum class SelectionDomain {
    ProjectObject,
    Geometry,
    Mesh
};
```

### 4.2 SelectionKind

```cpp
enum class SelectionKind {
    Object,
    Body,
    Face,
    Edge,
    Vertex,
    Node,
    Element,
    Facet
};
```

Alpha.3.2 active user-visible kinds:

```text
Object
Body
Face
```

The remaining kinds are declared now to avoid redesign but are activated later.

### 4.3 SelectionItem

Recommended contract:

```cpp
struct SelectionItem {
    SelectionDomain domain{SelectionDomain::Geometry};
    SelectionKind kind{SelectionKind::Body};
    ObjectId projectObjectId{InvalidObjectId};
    GeometryEntityId geometryEntityId{InvalidGeometryId};
    GeometryEntityId parentGeometryId{InvalidGeometryId};
    MeshEntityId meshEntityId{InvalidMeshId};
    quint64 sourceRevision{0};
};
```

Identity comparison should use the active domain/kind + entity identity. `sourceRevision` is freshness metadata, not the sole identity key.

### 4.4 SelectionOperation

```cpp
enum class SelectionOperation {
    Replace,
    Add,
    Remove,
    Toggle,
    Clear
};
```

### 4.5 SelectionManager state

The manager owns:

```text
policy
preselection
current selection collection
primary selection
```

Recommended public behavior:

```cpp
void setPolicy(const SelectionPolicy &policy);
void setPreselection(std::optional<SelectionItem> item);
void apply(const SelectionItem &item, SelectionOperation operation);
void clear();
void clearPreselection();
void invalidateGeometryRevision(quint64 currentRevision);

const QVector<SelectionItem> &items() const;
std::optional<SelectionItem> primary() const;
std::optional<SelectionItem> preselection() const;
```

Signals:

```cpp
void selectionChanged();
void preselectionChanged();
void policyChanged();
```

Rules:

- no duplicate entities,
- deterministic insertion order,
- primary = last committed entity unless explicitly changed,
- removing primary selects the newest remaining item as primary,
- stale geometry revision clears geometry preselection/current selection,
- policy changes remove incompatible transient selection rather than leaving hidden invalid state.

## 5. SelectionPolicy

The policy is context, not persistent engineering data.

Recommended fields:

```cpp
struct SelectionPolicy {
    SelectionDomain domain{SelectionDomain::Geometry};
    QSet<SelectionKind> allowedKinds;
    bool allowMultiple{true};
    bool visibleOnly{true};
};
```

Initial policy presets:

```text
Neutral Geometry       → Body, Face
Material Assignment    → Body
Surface Scope          → Face
Contact Side           → Face
Body Mesh Control      → Body
Face Mesh Control      → Face
```

Alpha.3.2 wires only the neutral Geometry Body/Face behavior. The other policy presets exist to prove the API can support future workflow migration.

## 6. ScopeReference foundation

Add a data-only contract, but do not migrate `SupportDefinition` / `LoadDefinition` yet.

Recommended representation:

```cpp
struct ScopeEntityReference {
    SelectionDomain domain{SelectionDomain::Geometry};
    SelectionKind kind{SelectionKind::Face};
    GeometryEntityId geometryEntityId{InvalidGeometryId};
    QString persistentKey;
};

struct ScopeReference {
    QVector<ScopeEntityReference> entities;
};
```

Alpha.3.2 may include conversion helpers:

```text
SelectionSnapshot → ScopeReference
ScopeReference → validation result
```

But current solver/analysis definitions continue to use `BoxFace` until a later controlled migration.

`sourceRevision` should not be serialized as if it were permanent identity. It may be recorded as diagnostic/binding metadata but must be refreshed when a scope is rebound to a newly loaded CAD document.

## 7. Viewport picking design

### 7.1 Picker returns topology hit, not selection state

Add:

```cpp
struct ViewportPickHit {
    bool valid{false};
    GeometryEntityId bodyId{InvalidGeometryId};
    GeometryEntityId faceId{InvalidGeometryId};
    std::array<double, 3> worldPoint{};
};
```

`vtkCellPicker` resolves the display cell. The Viewport translates that cell through provenance into `bodyId + faceId`.

The SelectionPolicy decides whether the selected entity becomes Body or Face.

This prevents the rendering layer from owning application selection semantics.

### 7.2 Move click classification to Qt-side selection input

The current `Dynamics26InteractorStyle` owns a left-click pick callback. That path lacks clean macOS modifier semantics and cannot support hover/preselection well.

Recommended Alpha.3.2 change:

- keep `ViewportInputRouter` as the sole navigation classifier;
- add `ViewportSelectionController` as a separate Qt event filter;
- retire the application pick decision from `Dynamics26InteractorStyle`.

New files:

```text
gui/viewport/ViewportSelectionController.h
gui/viewport/ViewportSelectionController.cpp
```

Responsibilities:

- track plain-left press/release distance,
- emit hover/preselection requests on mouse move when navigation is idle,
- classify Click / Shift+Click / Command+Click,
- clear on empty-area click,
- clear on Esc,
- participate in secondary-click behavior,
- never move the camera.

### 7.3 Filter order / navigation collision

Install event filters so navigation gets first refusal for navigation gestures:

```text
Mouse Event
   ↓
ViewportInputRouter
   ├── consumes middle drag / Option+left / wheel / native gesture
   └── otherwise passes through
          ↓
ViewportSelectionController
```

If Qt event-filter order requires reverse installation, install them in the corresponding order so navigation is evaluated first.

Selection controller must never commit a pick after Orbit/Pan/Zoom begins.

### 7.4 macOS modifier contract

```text
Click             → Replace
Shift + Click     → Add
Command + Click   → Toggle
Empty click       → Clear
Esc               → Clear
```

On Qt/macOS the physical Command key maps through Qt's Control shortcut semantics; the project must continue avoiding `Qt::META` for the Command contract.

Option/Alt remains reserved for Orbit/navigation and is not used for selection modification.

## 8. Geometry scene and multi-body support

Current normal geometry display shows only the first imported Body. Alpha.3.2 must close this because Body selection cannot be correct when the project tree and viewport disagree.

Recommended geometry viewport contract:

```cpp
void showGeometry(const QVector<TopologyTessellation> &bodies);
```

or equivalent scene object.

Two valid rendering implementations:

### Option A — aggregate polydata

Combine all body tessellations into one `vtkPolyData` and keep parallel cell provenance arrays:

```text
cell → bodyId
cell → faceId
```

Advantages:

- one pickable surface actor,
- simple `vtkCellPicker` contract,
- easy multi-body picking.

### Option B — actor per Body

Maintain one actor + provenance table per Body.

Advantages:

- easier per-Body hide/show/isolate later.

Alpha.3.2 recommendation: **Option A** for lower implementation risk. Alpha.3.4 can introduce actor visibility groups if hide/show/isolate requires it.

## 9. Selection rendering

Current `highlightActor` is tied to `cachedMesh`. Replace the single-purpose highlight path with independent semantic selection overlays.

Add render role:

```text
Preselection
```

Keep existing:

```text
Selection
```

Viewport state:

```text
cached CAD display scene + provenance
cached FEM mesh
preselection overlay
selection overlay(s)
```

Recommended API:

```cpp
void setGeometryPreselection(std::optional<SelectionItem> item);
void setGeometrySelection(const QVector<SelectionItem> &items);
void clearGeometrySelection();
```

Rules:

- Face selection rebuilds overlay from all display triangles carrying that Face ID.
- Body selection rebuilds overlay from all display triangles carrying that Body ID.
- Multi-selection displays all selected entities.
- selection does not depend on mesh generation.
- preselection and committed selection use different semantic palette roles.
- redraw/rebuild of the base scene must reapply the current selection snapshot.

## 10. Shell wiring

### 10.1 MainWindow ownership

`Dynamics26MainWindow` remains composition/wiring owner, not selection-state owner.

Add:

```text
SelectionManager *selection_
```

and put it into `ServiceContext` only if Details pages need explicit read access.

### 10.2 Replace ad-hoc geometry pick bridge

Retire:

```text
ViewportWidget::geometryPicked(quint64)
Dynamics26MainWindow::handleGeometryPick(quint64)
```

Replace with topology hit / selection request flow:

```text
ViewportSelectionController
   ↓
ViewportPickHit + SelectionOperation
   ↓
MainWindow / Selection coordinator
   ↓
SelectionManager
```

### 10.3 SelectionManager outputs

On `selectionChanged`:

```text
SelectionManager
  ├── Viewport selection overlays
  ├── Navigator current Body sync
  ├── DetailsHost selection summary
  ├── GraphicsWorkspace selection label
  └── EngineeringStatusBar selection text
```

### 10.4 Navigator synchronization

Keep Navigator `SingleSelection`.

Rules:

- Navigator Body click → project object changes and creates/replaces Geometry Body selection.
- Viewport Body selection → corresponding Navigator Body becomes current object.
- Viewport Face selection → parent Body becomes/stays Navigator current object.
- Faces are not inserted into the project tree as ordinary child nodes.

A reentrancy guard or signal blocker is required to prevent viewport→navigator→viewport loops.

The current `ProjectObject::tag` already carries the Body GeometryEntityId for imported body nodes and can remain the Body bridge for Alpha.3.2.

## 13. Secondary-click contract

Current viewport context menu is view-oriented. Alpha.3.2 establishes only the selection semantics:

- secondary click on already-selected entity → preserve selection, open menu;
- secondary click on unselected entity → Replace selection with that entity, then open menu;
- secondary click on empty area → do not accidentally clear unless explicitly decided by the context-menu UX;
- right click never starts camera motion.

Selection-specific commands may remain minimal until Alpha.3.4.

---

## 14. Geometry change / stale selection handling

On successful STEP import/replace/clear:

```text
GeometryService::changed
  ↓
SelectionManager clears geometry preselection/current selection
  ↓
Viewport overlays clear
  ↓
new CAD revision/scene loads
```

No stale GeometryEntityId may remain highlighted after geometry replacement.

A current selection whose `sourceRevision != GeometryService::summary().revision` is invalid and must be removed.

This is runtime invalidation only. Cross-session scope rebind remains Alpha.3.4.

## 15. Existing analysis scope compatibility

Alpha.3.2 does not change:

```text
SupportDefinition::scope : BoxFace
LoadDefinition::scope    : BoxFace
```

The current structured HEX8 + axis-aligned STEP-box solve path remains intact.

A later milestone can migrate a validated `ScopeReference` into AnalysisService using document commands and schema migration.

This restriction is deliberate: selection architecture must become reliable before it becomes solver input.

## 17. Test design

### 17.1 Geometry provenance test

Extend the existing generated OCCT box test.

Required assertions:

- imported box has exactly six Face entities,
- topology tessellation triangle count > 0,
- `triangleFaceIds.size() == triangles.size()`,
- every triangle maps to a valid Face entity,
- every mapped Face has the tessellated Body as parent,
- a box uses all six Face IDs,
- `sourceRevision == document.revision()`.

### 17.2 SelectionManager unit test

No VTK required.

Cases:

- Replace,
- Add,
- duplicate Add rejected,
- Toggle add/remove,
- Remove,
- Clear,
- primary-selection changes,
- policy rejects incompatible kind,
- policy change removes incompatible state,
- stale revision invalidates geometry selection,
- preselection never enters current selection.

### 17.3 macOS modifier contract test

Synthetic Qt events:

- plain left click → Replace,
- Shift+click → Add,
- Qt Control/Command semantic click → Toggle,
- Option+left remains navigation and never selection,
- Esc clears.

### 17.4 Navigation collision regression

Preserve all current navigation tests and add:

- middle orbit emits no selection request,
- Shift+middle pan emits no selection request,
- Option+left orbit emits no selection request,
- wheel zoom emits no selection request,
- trackpad pan/pinch emits no selection request,
- left drag beyond click threshold emits no committed selection.

### 17.5 Viewport picking test

Offscreen VTK scene with known cell provenance:

- picker resolves Body and Face IDs,
- Body filter returns Body,
- Face filter returns Face,
- empty pick clears for normal click,
- selection overlay contains every triangle belonging to the selected Face,
- multi-selection renders multiple Faces,
- preselection does not replace committed selection.

### 17.6 Multi-body test

Build/display at least two Bodies or two synthetic topology tessellations.

Assertions:

- both Bodies are visible,
- both are pickable,
- Body selection returns correct ID,
- Face selection remains attached to the correct parent Body.

### 17.7 Shell synchronization test

Where practical without full GUI automation:

- Navigator Body → SelectionManager Body,
- Viewport Body → Navigator current Body,
- Viewport Face → Navigator parent Body,
- Details summary reflects count/type/primary,
- no recursive signal loop.

## 20. Alpha.3.2 exit criteria

Alpha.3.2 is complete only if all statements below are proven:

### Data / topology

- real CAD Face IDs survive OCCT tessellation into the display provenance map;
- triangle index is never treated as CAD identity;
- multi-body imported geometry is represented consistently in Navigator and viewport;
- stale geometry revision clears transient selection.

### Interaction

- Body click works before mesh generation;
- Face click works before mesh generation;
- Shift add works;
- Command toggle works;
- empty click / Esc clear works;
- hover is visually different from selection;
- Orbit/Pan/Zoom never cause accidental selection.

### UI synchronization

- Navigator Body and viewport Body remain synchronized;
- viewport Face keeps parent Body as project current object;
- Inspector can show project object and geometry selection as separate states;
- status feedback reports meaningful Body/Face information.

### Regression

- existing geometry import still works;
- existing structured HEX8 mesh generation still works;
- current `BoxFace` BC/load solve path still works;
- existing viewport navigation test remains green;
- project migration remains green;
- no Fortran solver behavior changes.

### Native validation

- Apple Silicon arm64 build passes;
- Light Mode passes;
- Dark Mode passes;
- physical mouse interaction is user validated;
- physical trackpad interaction is user validated.

## 22. Final implementation principle

Alpha.3.2 must remove the current assumption that "a picked VTK cell is the engineering selection".

The permanent contract is:

```text
VTK Cell
  ↓ display provenance
CAD Face + Body
  ↓ selection policy
SelectionItem
  ↓ user action
Transient Selection
  ↓ later Apply/Assign
Persistent Engineering Scope
```

This contract is the required foundation for professional Material assignment, BC/load scoping, Contact pairs, local mesh controls and future FEM Node/Element selection without rewriting the GUI architecture again.
