# Dynamics26 V1.1.0-alpha.3.3 — CAD Topology Selection Technical Design

**Milestone:** V1.1.0-alpha.3.3 — CAD Topology Selection  
**Engineering core:** V1.0.2 — unchanged  
**Baseline:** V1.1.0-alpha.3.2 Selection & Scoping Foundation  
**Branch:** `main`  
**Status:** approved implementation plan  
**Date:** 2026-08-31

## 1. Scope decision

Alpha.3.3 is deliberately narrow. It adds real CAD **Edge** and **Vertex** selection on top of the verified Body/Face selection foundation.

This milestone does **not** include FEM Node/Element/Facet selection, rectangle/box selection, through/interior selection, candidate cycling, Named Selection objects or advanced connected/similar selection.

The release sequence is intentionally split to reduce integration risk:

```text
V1.1.0-alpha.3.2
Body / Face Selection Foundation
        ↓
V1.1.0-alpha.3.3
CAD Edge / Vertex Selection
        ↓
V1.1.0-alpha.3.4
FEM Node / Element / HEX8 Boundary Facet Selection
        ↓
V1.1.0-alpha.3.5
Visible Box / Window Selection
        ↓
V1.1.0-alpha.3.6
Named Selection + Scope Workflow
        ↓
V1.1.0-alpha.4
Integrated Modeling Workflow + Preflight
```

Through/interior selection and ambiguity/candidate cycling are not allowed to block this sequence. They may become a separate advanced-selection milestone if real acceptance testing proves that they are necessary.

## 2. Non-negotiable architecture rules

The existing rule remains unchanged:

> CAD Geometry != Display Tessellation != FEM Mesh

For Alpha.3.3 this becomes:

```text
TopoDS_Edge
   ↓ display discretization
VTK line cell
   ↓ provenance lookup
GeometryEntityId(Edge)

TopoDS_Vertex
   ↓ display point
VTK point
   ↓ provenance lookup
GeometryEntityId(Vertex)
```

A VTK line index or VTK point index is never a CAD topology identity.

Selection remains transient view state and is not written to the document Undo stack.

## 3. Research-driven decisions

### 3.1 Professional CAE behavior

Commercial CAE tools keep topology/entity filters explicit and procedure-aware. Body, Face, Edge and Vertex are separate selection levels; advanced area/depth/cycling operations are separate interaction concerns.

Dynamics26 decision:

- **ADOPT:** explicit Body / Face / Edge / Vertex filter levels.
- **ADOPT:** context-aware `SelectionPolicy`.
- **ADOPT:** nearest/visible click behavior before advanced ambiguity resolution.
- **DEFER:** candidate cycling.
- **DEFER:** visible rectangle selection to Alpha.3.5.
- **DEFER:** through/interior selection to a separate advanced stage if required.

### 3.2 OCCT topology identity

`TopExp_Explorer` traversal is not used as proof that shared topology is unique. Alpha.3.3 uses canonical body-local indexed topology maps (`TopTools_IndexedMapOfShape` / `TopExp::MapShapes`) for Face, Edge and Vertex identity.

Shared topology must be represented once per Body:

```text
Face A ─┐
        ├── Edge 17   ← one CAD Edge entity
Face B ─┘
```

For a rectangular box the canonical baseline is:

- 6 unique Faces,
- 12 unique Edges,
- 8 unique Vertices.

### 3.3 VTK picker roles

Alpha.3.3 does not introduce `vtkHardwareSelector`.

- Body / Face: existing surface actor + `vtkCellPicker`.
- Edge: dedicated CAD edge display actor + cell picking.
- Vertex: dedicated CAD point representation + point picking/tolerance.

Area selection is a later milestone.

## 4. Current-source gaps to close

### 4.1 Edge and Vertex entities are not fully cached as OCCT topology

The current importer creates Edge/Vertex `GeometryEntity` records but does not maintain the same explicit GeometryEntityId ↔ TopoDS subshape mapping used for Body/Face selection.

Alpha.3.3 must make Edge/Vertex first-class topology identities.

### 4.2 Shell/surface fallback is incomplete

When a STEP root contains no solid, the importer creates a fallback Body and Face entities. Edge/Vertex creation must be made consistent with the solid path.

### 4.3 Existing Face behavior must not regress

Alpha.3.2 Face provenance is verified. The new canonical map must cross-check Face topology and preserve the existing Body/Face display provenance API behavior.

## 5. Phase A — Canonical OCCT topology identity

### Goal

Build one canonical topology table per imported Body.

Conceptually:

```text
BodyTopologyCache
- bodyId
- ordered/canonical Faces
- ordered/canonical Edges
- ordered/canonical Vertices
- sourceRevision
```

Implementation direction:

```cpp
TopTools_IndexedMapOfShape faceMap;
TopTools_IndexedMapOfShape edgeMap;
TopTools_IndexedMapOfShape vertexMap;

TopExp::MapShapes(bodyShape, TopAbs_FACE, faceMap);
TopExp::MapShapes(bodyShape, TopAbs_EDGE, edgeMap);
TopExp::MapShapes(bodyShape, TopAbs_VERTEX, vertexMap);
```

Requirements:

1. Face IDs remain compatible with the verified tessellation provenance path.
2. Edge IDs map to real unique `TopoDS_Edge` subshapes.
3. Vertex IDs map to real unique `TopoDS_Vertex` subshapes.
4. `persistentKey` remains deterministic within the imported topology ordering.
5. Solid and shell/surface import paths use the same topology-registration helper.
6. Import fails safely if topology bookkeeping becomes inconsistent.

### Phase A acceptance

For a generated STEP box:

- exactly 6 Face entities belong to the Body,
- exactly 12 unique Edge entities belong to the Body,
- exactly 8 unique Vertex entities belong to the Body,
- every entity has a non-empty persistent key,
- every Edge/Vertex parent is the Body,
- no duplicate GeometryEntityId maps to the same canonical body-local Edge/Vertex entry,
- existing Face tessellation provenance still passes.

No user-visible Edge/Vertex picking is claimed at the end of Phase A.

## 6. Phase B — Edge / Vertex display provenance

### Edge display

A CAD Edge is discretized independently from surface-triangle edges.

Target contract:

```text
EdgeDisplayTessellation
- points
- line segments
- lineEdgeIds
- sourceGeometryId / Body
- sourceRevision
```

A display line segment only carries provenance to a CAD Edge.

Curve discretization should use an OCCT curve adaptor/deflection-based discretizer and must fail safely for unsupported/invalid curves.

### Vertex display

Target contract:

```text
VertexDisplay
- points
- pointVertexIds
- sourceGeometryId / Body
- sourceRevision
```

Each display point maps explicitly to one CAD Vertex ID.

### Phase B acceptance

- lineEdgeIds.size == lineSegments.size,
- pointVertexIds.size == displayVertexPoints.size,
- all provenance IDs exist in `GeometryDocument`,
- kind/parent/revision validation passes,
- no display primitive ID is used as CAD topology identity.

## 7. Phase C — Viewport picking and preselection

Extend the geometry filter to:

```text
Selection [ Body | Face | Edge | Vertex ]
```

Behavior:

- Click → Replace,
- Shift+Click → Add,
- Command+Click → Toggle,
- empty click → Clear,
- Esc → Clear,
- hover → Preselection only,
- secondary click preserves/replaces selection according to the Alpha.3.2 contract.

Edge mode must pick only the dedicated Edge representation; Vertex mode must pick only the Vertex representation. Face/Body actors must not steal Edge/Vertex picks.

Picking tolerance must make Vertex selection usable on Retina displays without changing CAD geometry identity.

## 8. Phase D — Shell synchronization

Viewport Edge/Vertex selection must not create one Navigator node per topology subentity.

Expected behavior:

```text
Viewport: Edge 37 selected
Navigator: Body 1 current
Inspector:
  Type      Edge
  Selected  4
  Primary   Edge 37
  Body      Body 1
```

The same rule applies to Vertex.

Selection remains outside document Undo/Redo.

## 9. Phase E — Tests and CI

Required automated evidence:

### OCCT topology regression

- generated box: 6 Faces / 12 Edges / 8 Vertices,
- shared topology uniqueness,
- solid path,
- shell/surface fallback path,
- Face provenance regression.

### Display provenance regression

- line → Edge provenance,
- point → Vertex provenance,
- stale revision rejection.

### Real VTK picker regression

Offscreen native-arm64 tests must prove:

```text
VTK line cell → provenance table → CAD Edge ID
VTK point     → provenance table → CAD Vertex ID
```

### Selection-state regression

- single Edge/Vertex,
- multi Edge/Vertex,
- Shift Add,
- Command Toggle,
- primary stability,
- hover/preselection separation,
- policy filtering,
- stale geometry revision invalidation.

### Shell acceptance

- Edge/Vertex keeps parent Body as current project object,
- Inspector summary is correct,
- selection does not modify `QUndoStack`,
- navigation does not create accidental topology selection.

## 10. Performance rules

Hover and selection must not rebuild CAD topology or remesh the model.

The target path is:

```text
scene already built
→ picker returns primitive index
→ provenance lookup
→ update preselection/selection overlay
```

No OCCT re-import, no display tessellation rebuild and no FEM mesh rebuild are allowed on pointer move.

## 11. Explicit OUT scope

Alpha.3.3 does not include:

- FEM Node selection,
- FEM Element selection,
- FEM Facet selection,
- mesh-generation selection identity,
- rectangle/box/window selection,
- `vtkHardwareSelector`,
- through/interior/frustum selection,
- candidate cycling,
- connected/tangent-chain selection,
- similar selection,
- grow/shrink,
- Named Selection objects,
- hide/show/isolate,
- BC/load/contact migration to reusable scopes,
- meshing algorithm changes,
- solver changes.

## 12. Risk register

| Risk | Severity | Mitigation |
|---|---:|---|
| Shared Edge duplicated | Critical | canonical IndexedMap topology |
| Shared Vertex duplicated | Critical | canonical IndexedMap topology |
| Alpha.3.2 Face IDs regress | Critical | Face cross-validation + existing provenance tests |
| Shell STEP lacks Edge/Vertex | High | common body-topology registration helper + shell test |
| VTK line/point index treated as CAD ID | Critical | explicit provenance arrays |
| Edge actor interferes with Face picking | High | active representation / PickFromList policy |
| Vertex target too small | Medium | picker tolerance + dedicated marker actor |
| Hover rebuilds geometry | High | immutable display scene + overlay updates only |
| Stale geometry selection survives replace/edit | Critical | sourceRevision invalidation |
| Navigator flooded with topology nodes | High UX | parent Body context only |
| Selection enters document Undo | High | transient SelectionManager regression |

## 13. Release closure criteria

Alpha.3.3 can move to engineering acceptance preview only when all automated criteria below are proven:

1. Canonical OCCT Face/Edge/Vertex topology map exists.
2. Box topology proves 6 Faces / 12 unique Edges / 8 unique Vertices.
3. Solid and shell/surface import paths are topology-complete.
4. Existing Body/Face selection regressions remain green.
5. Edge display line → CAD Edge provenance is explicit and tested.
6. Vertex display point → CAD Vertex provenance is explicit and tested.
7. Body/Face/Edge/Vertex filters change actual picker behavior.
8. Single and multi Edge selection pass.
9. Single and multi Vertex selection pass.
10. Shift Add and Command Toggle pass.
11. Hover/preselection is separate from committed selection.
12. Parent Body Navigator/Inspector context is preserved.
13. Geometry revision invalidates stale Edge/Vertex selection.
14. Selection never enters document Undo.
15. Orbit/pan/zoom regression tests remain green.
16. Native Apple Silicon GUI and topology tests pass.

Final closure still requires real macOS user acceptance for:

- mouse Edge/Vertex picking,
- trackpad/navigation collision,
- hover feel,
- selection readability in Light Mode,
- selection readability in Dark Mode.

No stable tag/release is created before that distinction is explicit.
