# Dynamics26 V1.1.0-alpha.3.4 — FEM Selection Technical Design

**Milestone:** V1.1.0-alpha.3.4 — FEM Node / Element / Boundary Facet Selection  
**Engineering core:** V1.0.2 — unchanged  
**GUI baseline:** V1.1.0-alpha.3.3 CAD Topology Selection  
**Branch:** `main`  
**Status:** approved implementation plan  
**Date:** 2026-08-31

## 1. Scope decision

Alpha.3.4 extends the verified transient selection architecture from CAD topology to generated FEM entities.

IN scope:

- FEM Node click/hover selection,
- FEM Element click/hover selection through a visible boundary face,
- HEX8 Boundary Facet click/hover selection,
- Replace / Shift Add / Command Toggle / Clear semantics,
- Primary selection,
- Mesh-generation stale invalidation,
- Navigator/Inspector parent Mesh context,
- semantic selection/preselection overlays,
- persistent mesh-scope data contract foundation,
- Apple Silicon automated regression gates.

OUT of scope:

- rectangle/window/box selection,
- `vtkHardwareSelector`,
- interior/pick-through selection,
- hidden interior Node/Element click selection,
- candidate cycling,
- grow/shrink/connected/similar selection,
- Named Selection document objects,
- BC/Load/Contact migration to reusable scope objects,
- meshing algorithm changes,
- solver changes.

These deferred items belong to Alpha.3.5/Alpha.3.6 or later.

## 2. Non-negotiable identity rule

The existing invariant remains mandatory:

> CAD Geometry != Display Tessellation != FEM Mesh

For FEM selection the equivalent rule is:

```text
SimulationMesh::MeshNode.id
   ↓ display provenance
VTK point/vertex primitive
   ↓ lookup
MeshEntityId(Node)

SimulationMesh::MeshFacet.id
   ↓ display provenance
VTK boundary quad cell
   ↓ lookup
MeshEntityId(Facet)

SimulationMesh::MeshFacet.ownerElementId
   ↓ visible boundary element pick
VTK boundary quad cell
   ↓ lookup
MeshEntityId(Element)
```

A VTK point index, glyph cell index or polydata cell index is never a FEM Node/Element/Facet identity.

## 3. Visible-click rule

Alpha.3.4 is intentionally a visible-selection milestone.

- Node mode exposes boundary-visible mesh nodes for pointer picking.
- Facet mode picks actual `SimulationMesh::boundaryFacets`.
- Element mode resolves a picked boundary facet to its `ownerElementId`.
- An interior HEX8 element with no exposed boundary facet is not pointer-selectable in Alpha.3.4.

Interior/window selection is deferred to Alpha.3.5, where GPU-backed area/depth selection can be evaluated explicitly.

## 4. Mesh selection scene

Add a VTK-independent `MeshSelectionScene` contract.

Conceptually:

```text
MeshSelectionScene
- meshGeneration
- points
- nodeIds
- boundaryQuads
- facetIds
- ownerElementIds
```

Responsibilities:

1. Validate unique/non-invalid Node, Element and Facet IDs.
2. Validate every boundary-facet node reference.
3. Validate every boundary facet owner Element.
4. Preserve exact MeshEntityId provenance for each display primitive.
5. Resolve visible primitive → SelectionItem.
6. Resolve SelectionItem → overlay point/cell indices.
7. Reject stale mesh generation.

The scene does not own `SimulationMesh` and does not mutate solver/mesher data.

## 5. Selection lifecycle

`SelectionItem::sourceRevision` is a generic source-generation guard:

- Geometry domain: `GeometryDocument::revision()`.
- Mesh domain: `MeshService::generation()`.

Add `SelectionManager::invalidateMeshGeneration(currentGeneration)`.

A successful mesh regeneration must invalidate committed/preselected FEM entities from the previous generation. CAD selection must not be cleared by mesh-generation invalidation, and mesh selection must not be cleared by CAD-revision invalidation.

## 6. Selection policies

Add explicit mesh presets:

```text
MeshNodeScope    → Mesh / Node
MeshElementScope → Mesh / Element
MeshFacetScope   → Mesh / Facet
```

All three allow multi-selection and use visible-only semantics in Alpha.3.4.

## 7. Graphics filter UX

Geometry context remains:

```text
Selection [ Body | Face | Edge | Vertex ]
```

Mesh context becomes:

```text
Selection [ Node | Element | Facet ]
```

Only filters meaningful to the current domain are shown/enabled. Switching filter changes the actual picker target, not only toolbar state.

## 8. VTK representation and picking

### Node

Use a dedicated mesh-node point/vertex actor whose point order is backed by `MeshSelectionScene::nodeIds`. Do not use glyph output cell IDs as Node IDs.

### Facet

Use the boundary-surface quad actor. Cell index resolves through `MeshSelectionScene::facetIds`.

### Element

Use the same visible boundary-surface actor, but resolve the picked boundary cell through `ownerElementIds`.

The active pick list must contain only the actor relevant to the current filter so geometry/load/result actors cannot steal a pick.

## 9. Overlay semantics

- Node selection: semantic point overlay.
- Facet selection: selected boundary quad overlay.
- Element selection: all exposed boundary facets belonging to selected owner Element.
- Preselection remains visually distinct from committed selection.
- Light/Dark colors continue to come from `RenderRole::Selection` and `RenderRole::Preselection`.

No hard-coded product color is introduced.

## 10. Shell synchronization

A FEM subentity does not become a Project Navigator node.

Expected behavior:

```text
Viewport: Node 142 selected
Navigator: Mesh current
Inspector: Mesh object + secondary selection summary

Viewport: Element 37 selected
Navigator: Mesh current
Inspector: Mesh object + secondary selection summary
```

Raw selection remains transient and never enters `QUndoStack`.

## 11. Persistent mesh scope foundation

Extend `ScopeEntityReference` with `meshEntityId` and add mesh-scope build/validation helpers.

A mesh scope records:

- `SelectionDomain::Mesh`,
- Node/Element/Facet kind,
- MeshEntityId,
- source mesh generation.

After mesh regeneration, an old mesh scope is stale and must not be silently accepted.

Named reusable scope objects remain Alpha.3.6.

## 12. Tests

Required evidence:

### Data contract

- Node/Element/Facet IDs remain distinct from VTK primitive indices.
- invalid node references fail scene construction.
- invalid owner Element fails scene construction.
- stale generation produces no overlay/pick item.

### Selection state

- single + multi Node,
- single + multi Element,
- single + multi Facet,
- Shift Add,
- Command Toggle,
- primary stability,
- hover/preselection separation,
- mesh generation invalidation,
- geometry revision invalidation does not erase Mesh domain by mistake.

### Real VTK picker

Offscreen Apple Silicon verification must prove:

```text
VTK boundary point/cell
→ MeshSelectionScene provenance
→ MeshEntityId
```

### Shell acceptance

- Node/Element/Facet selection keeps Mesh as Navigator current object,
- Inspector selection summary reflects kind/count,
- transient FEM selection creates no Undo entry,
- camera navigation regressions remain green.

## 13. Acceptance criteria

Alpha.3.4 automated engineering closure requires:

1. MeshSelectionScene exists and validates provenance.
2. Mesh generation is the stale-selection guard.
3. Node filter changes actual picker to Node representation.
4. Element filter resolves visible boundary cell to owner Element ID.
5. Facet filter resolves visible boundary cell to Facet ID.
6. Single and multi Node selection pass.
7. Single and multi Element selection pass.
8. Single and multi Facet selection pass.
9. Shift Add and Command Toggle pass.
10. Hover/preselection remains separate.
11. Navigator/Inspector remain at the parent Mesh project object.
12. Mesh selection never enters document Undo.
13. CAD and FEM identity domains remain isolated.
14. Light/Dark semantic contrast guards remain green.
15. Native arm64 GUI and dedicated mesh-selection tests pass.

Final UX closure still requires real macOS user acceptance for mouse/trackpad selection feel and Light/Dark readability. No stable tag/release is implied by automated closure alone.
